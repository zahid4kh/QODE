# QODE chat (agent)

## agent (AI panel)

`ai/AiHub` is the central agent view (no longer in the right-hand stack) and hosts `agent/AgentPanel` and, as a second page, the Claude Code view (`claudecode/ClaudeCodePanel`, [claude-code.md](claude-code.md)); the agent's widgets paint with `Theme::agentView()` (window / panel / editorBg / border swapped for the darker `agentBg` / `agentPanel` / `agentInput` / `agentBorder` fields), and `AgentPanel::resizeEvent` keeps transcript, input and the notice row (`m_noticeRow`, e.g. "No API key") a centred 920 px column (the old plan-and-edit chat is gone). The chat cannot be closed from its header; there is no close button or `closeRequested` signal, and it is hidden only through `m_aiAct` while the editor column is visible. The input frame `aiInputBox` gets the accent border while the text edit has focus: `AgentPanel::eventFilter` sets the dynamic property `focused` and re-polishes, matched by the `[focused="true"]` stylesheet selector. The Send/Stop button `aiSend` is a fixed 28×28 with a 14 px radius, because a stylesheet radius makes a circle only when it is half the widget size, and a size that grows with UI zoom turned it into a rounded square. The model list is `ai/AiModels` (shared with the inline edit box, [editor.md](editor.md)), plus a free-text "other model id" field. The agent runs on **Gemini or Claude**: `AiEnv::providerForModel` (`claude-*` → Claude) picks the provider, keys are per provider (`AiEnv::apiKey(provider, root)`: `~/.config/QODE-AGENTIC/gemini.key` / `claude.key`, else `GEMINI_API_KEY` / `ANTHROPIC_API_KEY`, else `.env*`; `AiKeyDialog(provider)`), the model picker lists both with their logos (`Theme::brandGemini/brandClaude`; `gemini.svg` / `claude.svg`, while `claudecode.svg` is reserved for the Claude Code view, see [claude-code.md](claude-code.md)) and an Effort submenu for Claude (`SettingsManager::aiEffort`). A chat never changes provider: picking a model of the other provider in a non-empty chat asks to start a new chat (`AgentPanel::chooseModel`), and loading a chat switches the model back to its provider (`followChatProvider`). `agent/AgentRun` is one class for both: the Gemini half is in AgentRun.cpp, the Claude half (`POST /v1/messages`, streamed) in `AgentRunClaude.cpp`; `ai/ClaudeClient` holds the per-model knowledge (`thinkingFor` adaptive+summarized / budget on ≤4.5, `effortFor`, `maxTokensFor`, `offersFallbacks` → `fallbacks: "default"`, `bindsThinking` → `block_binding: drop_block`), headers (`ANTHROPIC_BASE_URL` overrides the endpoint, useful for a mock server) and the non-streaming call used by /compact.

**The Claude history must stay append-only within a run** (5.x models bind thinking blocks to the exact prefix; never prune or edit earlier turns — the Gemini side's `pruneOldResults` is not used for Claude); tools come from `AgentTools::claudeToolsJson` (same specs, `eager_input_streaming`, invalid JSON → `is_error` tool_result). Agent chats are a separate format in `<project data dir>/agent-chats/` (`agent/AgentSession`: a turn is an ordered list of Thought / Text / Tool blocks; `Session::history()` replays prompts + final answers + a one-line list of actions, not the tool traces). `agent/AgentRun` streams `streamGenerateContent?alt=sse` with `thinkingLevel` + `includeThoughts`, echoes the model parts verbatim (thought signatures), runs every `functionCall` through `AgentTools::execute` on the UI thread, sends the results back and repeats (40 requests max, old big tool results are pruned to previews, 429/503 retry with the server's delay; Stop = `cancel()` which also kills a running command). `agent/AgentTools` holds the tools (list_directory, directory_tree, find_files, search_text, semantic_search, read_file, find_text_range, get_open_files, git_status/diff, edit_range, replace_text, insert_lines, create_file/directory, move/copy/delete_path, run_command); every path is confined to the project root (secrets and `.git` refused), `Risk::Dangerous` tools (delete_path, run_command, git_*) go through the `approve` hook (a dialog with Allow once / Allow for this chat / Deny), edits reuse `AiWorkspace::apply` so they are unsaved, undoable editor-tab changes, and `flushEdits` saves the touched documents before commands/git/moves so the disk matches. `agent/AgentTurnView` renders a turn live (throttled Markdown, thoughts fold when something else follows, edits become `AiChangeCard` diffs). New tools: add a `Spec` in `AgentTools::registerAll` (with a `group` when only some projects need it, see below).


**run_command's shell and Windows** (Phase 6 of the Windows port): `Platform::chatShells / chatShell(id) / setChatShellCommand`. Unix: `/bin/bash -c`, the only shell, so no menu and the prompt and run_command text are as before. Windows: PowerShell (pwsh 7 when installed, else Windows PowerShell 5.1) by default, Git Bash as the alternative (the model menu's "Commands run in" submenu, setting `ai/shell`, `SettingsManager::aiShell`, shown only when there is more than one shell). `AgentPanel::startRun` calls `AgentTools::setShell` before each run, which rewrites the run_command declaration (`runCommandDescription`: PowerShell 5.1 has no && / ||, `$env:NAME`, `.\gradlew.bat`), and `AgentTools::environmentPrompt` adds a "This computer" section (Windows version, shell, path forms) after the base instructions; `baseInstructions` says Windows instead of Linux and names winget instead of sudo. PowerShell is started with a fixed `-Command` bootstrap that reads the command from the environment variable `QODE_CHAT_SCRIPT` (a temporary `.ps1` in `QODE_CHAT_SCRIPT_FILE` when it is longer than 30000 characters, deleted with the QProcess) and removes the variable before running it: with `-EncodedCommand` Windows PowerShell writes errors to stderr as CLIXML (`#< CLIXML <Objs…>`, even with `-OutputFormat Text`), and `-Command` with the command inline would need cmd-style quoting. The bootstrap sets UTF-8 output (`[Console]::OutputEncoding`, `$OutputEncoding`) and `$ProgressPreference = 'SilentlyContinue'`; lines after the command turn the result into bash's exit code (0 when the last command succeeded, else `$LASTEXITCODE`, else 1; -Command alone only gives 0 / 1). Parse errors show the command's own line numbers. `-ExecutionPolicy Bypass` lets npm.ps1 and a project's scripts run. Output is decoded with `Platform::decodeOutput` (`clipTail` starts at a whole UTF-8 character, else a cut euro sign made the tail read as ANSI). `commandDenied` (`agent/AgentToolHelpers.h`) also blocks Windows' runas / -Verb RunAs / gsudo, format / diskpart / Format-Volume, Stop-/Restart-Computer, iwr | iex and DownloadString, Credential Manager and DPAPI folders, HKLM registry writes, Defender / firewall settings, QODE's own key files and settings folder (both OSes), and a recursive delete (Remove-Item / rm / ri / del / rd / rmdir with -r… or /s) of a drive root, ~, $HOME, $env:USERPROFILE / APPDATA…, %VAR% forms, * or . / .. (`windowsDeleteDenied`, per part between | ; &). Tool paths go through `Platform::fromShellPath` (`\` and /c/x, /mnt/c/x, /cygdrive/c/x on Windows), the root is compared with `samePath`, and approval dialogs show native paths. Tested with a GUI-subsystem scratch program (`chat-test`): UTF-8 (é € 中), exit codes 0 / 1 / 3 / 7, quotes, multi-line, && error, throw, a 15000- and a 40000-character command, Stop of a running ping (1.6 s, no process left), Git Bash quotes / UTF-8 / exit / stop, 28 denied and 15 allowed command lines.

**Shared with the Claude Code view** (both chats use `AgentTurnView`, `AiInput` and `MarkdownView`): `media/CopyButton` copies what its source returns and shows a tick and "Copied" for 1.5 s; `revealOnHover(host)` shows it only while the pointer is over the host (its place in the layout is kept, so rows do not shift). Code boxes in `MarkdownView` (chats and the Markdown preview) get one floating button at the header's right (`updateCopyButton` on mouse move and scroll, hidden on leave; the generated HTML has no copy link any more, `handleCopyLink` stays for `qode-copy:` URLs). A turn's footer row (`AgentTurnView`, with the stats) ends in a Copy button for the raw Markdown of its text items, no thoughts or tool rows (`replyText`); disabled while live, shown on hover and always on the last turn (`setCopyPinned`, kept by the panel). User bubbles have an icon-only one for the typed text. ↑ / ↓ recall earlier prompts (`AiInput::historyRequested`; the QODE chat recalls the open chat's user messages, `AgentPanel::recallPrompt`). The status line shows the elapsed time ("Thinking… · 12s", `agent::formatElapsed`, ticked by `m_clockTimer` while busy; compaction counts too).

**Ask about this / Quote this**: a reply's `MarkdownView` (`setChatActions`, set by `AgentTurnView::makeView`) has its own context menu: Copy, Copy Link Location over a link, Ask about this, Quote this, Select All, with icons (the Markdown preview gets the same menu without the two chat actions). The selection is taken as plain text without the U+202F padding of inline code pills. Quote this puts an `ai/AiQuote` card (removable) at the top of the input box; it goes with the next typed message and is cleared when the chat changes. Ask about this sends at once with `AiQuote::askPrompt()` and the selection as the quote, leaving the draft in the input (while a run is going it is staged in the input instead). The model gets `AiQuote::block(quote)` (`<quote>From your earlier reply:\n…\n</quote>`) ahead of the request inside `Message::sent`; `Message::quote` keeps it for the bubble, which shows the same card.

**Fix with QODE** (`window/MainWindowFix.cpp`, `AiHub::startFix` → `AgentPanel::startFix`): a failed terminal command (the terminal's floating button, see [terminal-git.md](terminal-git.md)) or errors in Tasks > Problems (the sparkles button for all errors of the list, or the context menu on one problem / one file) start a new chat (the current one when it is still empty) about the error. The user's bubble shows a short line ("Fix this: make failed (exit code 2).", "Fix the failing test in ShapeTest.", "Fix this error in calc.c:11."), the error as the quote card, and the files as pointed-at files. The quote reaches the model with its own lead (`AiQuote::block(quote, lead)`: "The command and its output in the terminal:", "From Tasks > Problems:" instead of "From your earlier reply:"). The request says what failed, where and with which exit code, asks for the cause to be fixed and the command (or a quicker check) run again, and carries an excerpt of each file around its error spots (±8 lines, merged, numbered, from the editor's copy when open, at most 4000 characters a file, headed "the whole file" or "lines 3-14 of 40" so the model knows when it need not read). The files: compiler problems found in the command's output, then `MainWindow::fixLocations` over the output (`path:line` absolute or relative to the command's folder or the project, Python's `File "…", line N`, JVM frames `(Name.java:12)` matched by file name when unique), only project files, never secret files (`AiEnv::isSensitive`) or files under node_modules / build / dist / target / .gradle / venv folders, at most 5. A failed command that holds the class of the last ▶ test run (`m_lastTestClass`, set in `runTest`) counts as a failing test: the test file goes first, and the request asks to fix the code under test unless the test itself is wrong, and to say which. The quote and request go through `maskSecrets`. While a run is going (or the chat cannot send yet), the line with `@file` mentions and the quote wait in the input instead, and `m_quoteLead` keeps the quote's lead for when it is sent. Tested with Gemini 3.5 Flash-Lite: a gcc typo (fixed without reading the file, rebuilt, exit 0), a Python ZeroDivisionError through two files (both attached, fixed, rerun), a failing JUnit test from the ▶ lens (Square.area fixed, not the test, the test rerun), one error from the Problems menu, and a Fix while a run was going.

**Codebase index** (`agent/CodeIndex`, `agent/CodeChunks`; the `semantic_search` tool). `AgentPanel` owns one `CodeIndex` per project. It is fed by `setProjectFiles`, by `EditorManager::documentSaved` (`fileChanged`), and by `keyChanged` after the Gemini key dialog. Every indexable text file (`indexableName`: no secrets, lock files, minified bundles, binaries, dependency folders; at most 512 KB and 40k files) is split into sections of about 50 lines (`codeindex::split`, at most 100). The split cuts in front of top-level declarations, after blank lines and at Markdown headings, and the comment above a declaration goes with it. Each section gets its declared names and the terms of its text (identifiers split at camelCase / snake_case, lightly stemmed, stop words dropped; names ×3, path ×2). Splitting runs on a worker thread and re-reads only files whose mtime/size changed. `search` re-stats the files in scope synchronously first, so changes made by a command or outside QODE are picked up. Unsaved editor buffers are passed as an overlay and searched in place of the file on disk, so the agent's own unsaved edits are found.

Ranking is BM25 over the terms (local, always on) and, when `ai/codeEmbeddings` is on (default) and a Gemini key exists, cosine similarity with `gemini-embedding-2` vectors (768 dims). Sections are embedded as `title: <path> <symbol> | text: …` and queries as `task: code retrieval | query: …`, the asymmetric format from `g-docs/embeddings.md`. Each ranking contributes its top 40 and they are merged by reciprocal rank fusion (k = 60). The model gets the sections as numbered lines, at most 60 lines / 4 KB each and about 12 KB in total, with the rest listed by place only. It never sees the index itself.

Vectors are stored int8-quantized under 16 bytes of SHA-1 of the embedded text in `~/.cache/QODE-AGENTIC/code-index/<project>.vec`. Only sections without a vector are sent (`batchEmbedContents`, up to 100 per request), also across restarts. Once a full pass has run, vectors of sections that no longer exist are pruned on save. The free tier allows about 30k tokens a minute, so a batch starts at 60k characters, halves and waits longer after a 429 (`m_batchChars` / `m_gapMs`), and grows again while requests succeed; one oversized batch would otherwise fail forever and also use up the quota the query embedding needs. A rejected key stops embedding until the key changes, and a project stops at 60k vectors. When the query cannot be embedded, the search falls back to keywords and says so in `note`. The header's search button shows the state (files, sections, sections embedded) and has "Search by meaning with Gemini embeddings" (off = nothing leaves the computer) and "Rebuild index".

**IDE tools** (`get_ide_state`, `set_theme`, `show_panel`, `open_file`, `set_option`, `editor_command`, `check_language_servers`, `install_language_server`) let the model operate the window. They reach it through one hook, `AgentTools::Hooks::ide(action, args)`: `AgentPanel::setIdeHandler` ← `AiHub::setIdeHandler` ← `MainWindow::wireIdeTools`, and `MainWindow::ideAction` (MainWindowIde.cpp) dispatches. AgentTools resolves and confines paths first; the window side drives the same QActions as the menus (`setChecked` on the checkable ones, so menus and settings stay in sync; `ideOptionActions` maps option names to actions). None asks for approval. The model only gets theme ids, names and a dark flag, never colours. `editor_command` opens the file and shows the editor column. Its editing commands (organize / remove unused / add missing imports and fix all through `applySourceActionsBlocking`, which waits up to 8 s for the server to start; `format` through `EditorManager::formatCurrent`) are snapshotted around the call and recorded in the journal, so `undo_changes` reverts them, and the changed lines become a diff card. `check_language_servers` reports status, `qode_can_install`, missing prerequisites (Node/npm, Python, Java 21), the distribution from /etc/os-release and `installHelp` for servers that are missing. `install_language_server` opens the same installer dialog as LSP > Download and Set Up (`installLspServer` returns false when the user closes it), so the user still starts the download. The system prompt tells the model to ask before installing and to give sudo commands as a code block, never run them (`run_command` blocks sudo anyway). Tool enums are added with `withEnum`, and the declarations stay constant for caching. The acting IDE tools take `done`. When every call of a round sets it and succeeds (`AgentTools::endsTurn`), `runTools` / `runClaudeTools` end the run without the follow-up request, because a one-line "Done" would otherwise cost a full round trip. The run's history is not kept, so `Message::actions()` lists the acting IDE calls (call text and result) next to edits and commands. Without that, a turn with an empty answer disappeared from `Session::history()`: the next prompt was merged into the earlier user turns, and the model redid the old requests (asked "is the terminal open?", it switched the theme again).

**Tool groups**: every declared tool costs tokens on every request, so tools that only some projects can use belong to a group (`Spec::group`; `AgentTools::allGroups`: `preview`, `servers`, `http`, `jvm_debug`), and `core` tools are always declared. Before each run `AgentPanel::prepareToolGroups` asks the window (`tool_groups` IDE action, `MainWindow::ideToolGroups`): `preview` with Qt WebEngine and a web dev server or an Expo app, `servers` with a web / Expo / Spring Boot / Ktor server, `http` with `.http` / `.rest` files or Spring Boot / Ktor, `jvm_debug` with `.java` / `.kt` files or a Gradle / Maven build. The declarations are part of the cached prefix (Gemini's implicit cache; Claude's system breakpoint covers the tools), so a chat's groups only grow: they are saved with the chat (`Session::toolGroups`), each run uses the saved ones plus the current ones in `allGroups` order, and a project that gains a capability costs one cache miss instead of flipping the tool set between runs. Inactive tools are neither declared nor callable ("… is not available in this project"). `AgentTools::groupPrompt` appends each active group's system-prompt section (only for groups with tools). `QODE_AGENT_DUMP_TOOLS=1` prints the groups and the declarations' size to stderr at each run. Measured on the Gemini declarations (characters / 4): core alone about 4.3k tokens (17.3k characters; Claude 18.7k), `preview` + `servers` about 1.7k more (plus a 1.6k-character prompt section), `jvm_debug` about 640, `http` about 140. Every group in every project would be about 6.8k tokens per request, so a C++ chat saves about 2.5k tokens per request and a web chat about 800.

**Server tools** (group `servers`; `agent/AgentToolsServers.cpp`, window side `window/MainWindowIdeServers.cpp`): `server_status`, `server_start`, `server_restart`, `server_stop`, `server_log` drive the servers QODE runs, by id: `web` (`DevServerBar`), `expo:<app folder>` (the preview's headless Metro, `ExpoBar::webServer`, which serves one app at a time), `spring` (`SpringBar`), `ktor` (`KtorBar`). `MainWindow::ideServers` lists them with start / stop / restart callbacks that go through the bars, so the command, environment and port are the toolbar's. The window calls return at once; `AgentTools` waits by polling `server_status` (`waitUntil` in `agent/AgentToolHelpers.h`, Stop honoured) until `DevServer::starts()` has moved past its value before the call and the state is no longer starting. Counting starts matters because a restart goes Running → Starting with no Stopped in between, and a fast server can pass through Starting between two polls. The wait is 120 s by default, 300 s at most. A start that fails answers with the log's last 60 lines; one still starting answers with the last 25 and a note. Start and restart ask first (they run project scripts; the dialog shows the command), and stop does not. Without a `server` argument the tools use the only server (`serverInfo`), because `server_status` without an id lists them all. A failed server's exit reason is the `failure` field: an `error` key in an IDE answer means the call itself failed, which once made every status call of a failed server fail. The prompt section tells the model to use these tools instead of `run_command`, which would wait for a server to end. Python web apps (Flask, Django) have no QODE server, so they stay with `run_command`. Tested with Gemini 3.5 Flash-Lite on a `python3 -m http.server` project: start, restart, a broken script diagnosed from the log (`No module named http.servre`), stop. The group adds about 540 tokens.

**Preview tools** (group `preview`; `agent/AgentToolsPreview.cpp`, window side `window/MainWindowIdePreview.cpp`): `preview_screenshot`, `preview_console`, `preview_set_viewport`, `preview_navigate`. Every call goes through `MainWindow::idePreview`. It shows the web preview (and switches its target when `server` is given) and refuses with a pointer to `server_start` while the target's server is not running. Then it waits up to 15 s for the page to load. The screenshot is `WebPreview::capturePage`. The panel shows a device scaled down (`zoomFactor`), so for the picture the view is laid out at zoom 1 at the device's CSS size behind a still image of the panel. It waits until `innerWidth x innerHeight` matches, plus 250 ms for the paint, grabs the view and restores the panel. The model therefore gets unscaled CSS pixels (a HiDPI grab is scaled back): phone 393x852 / 412x915, tablet 820x1180, desktop 1440x900 (Desktop is as tall as the panel on screen, which gave 1440x2164 pictures of mostly empty page), and `full_page` uses the scroll height up to 3000 px. The PNG travels in the IDE answer as `image` and `AgentTools::previewTool` moves it into `ToolResult::images`, the path MCP images already use for both providers. Every answer carries url, title, device, viewport and the console's error count with the first three errors. `preview_console` returns only entries newer than the last call (`ConsoleEntry::serial`, `MainWindow::m_previewConsoleRead`; `include_read` for all since the load). `preview_navigate` only opens dev-server paths (or reload / back) and waits for `loadsFinished` to move. `reload` on the screenshot saves edits first, for static servers without hot reload. None of them asks first. `QODE_AGENT_DUMP_IMAGES=<folder>` saves every picture sent to the model. Tested with Gemini 3.5 Flash-Lite on a static page whose header overflowed on phones and which threw a `TypeError`: it found both from a phone screenshot and the console, fixed the CSS with a media query, and checked phone and desktop screenshots (71 % of that run's input was cached). Navigate and reload were checked separately. With `servers`, the group brings the declarations to about 5.4k tokens (core 4.2k). `preview_click`, `preview_type` and `preview_eval` act in the page, so they ask first (the dialog shows the selector, the text or the code). Click and type run in an isolated world (`WebPreview::evaluate`, ApplicationWorld: same DOM, the page's listeners fire, no page globals). Typing sets the value through the prototype's native setter and dispatches input / change, so React-controlled fields notice. `submit` dispatches Enter and then `form.requestSubmit()`. An element is named by its text, placeholder, aria-label or name, never its value, which once showed the value from before typing. After a click or type the call waits 600 ms, and longer when a navigation started. `preview_eval` runs in the page's own world: indirect `eval` takes statements as well as expressions, a promise is awaited, and the result is stored under a key of its own and polled. The `runJavaScript` callback only touches shared state, so a callback that comes after a timeout cannot crash. Results are JSON clipped to 8000 characters. Tested on the test page's sign-up form: eval read the fields and ran an async fill-and-click, type + click and type with `submit` produced the page's "Thanks, …!".

**Terminal output** (`terminal_output`, a core tool): the user's terminal panel as the model's eyes when the user says "why did that fail?". `MainWindow::ideTerminalOutput` takes the shown pane (or the first pane of tab `tab`) through `TerminalPanel::panes`. It returns `Terminal::recentOutput` (the last lines of screen + scrollback, trailing blank lines dropped, at most 300 lines), the shell's real folder (`/proc/<pid>/cwd`, project-relative), whether a command holds the foreground (`commandRunning`) and the tab names. Before the text leaves QODE, `maskSecrets` (`agent/AgentToolHelpers.h`) hides `KEY=value` / `"key": "value"` pairs (api key, access key, secret, token, password, authorization / auth but not author, credential, private key, cookie, session; a value may start with `Bearer` / `Basic`), `Bearer …` anywhere, and well-known key formats (`sk-`, `sk-ant-`, `AIza`, GitHub, Slack, AWS `AKIA`). A backslash never counts as part of a value, so masking inside escaped JSON cannot eat an escape, because the terminal is the one place where the user may have printed a secret. Tested with Gemini 3.5 Flash-Lite: after `echo API_KEY=abcd1234secret` and `ls nosuchfile`, it explained the failure and quoted the echo as `API_KEY=[hidden]`.

**HTTP requests** (group `http`; `agent/AgentToolsHttp.cpp`, window side at the end of `window/MainWindowHttp.cpp`): `http_request` sends one request of a `.http` / `.rest` file by `# @name`, `### title` or line, through the HTTP panel exactly like the user's Send. That covers variables, the chosen environment, requests it depends on (sent first, listed as `sent_first`) and `# @prompt` dialogs. `environment` picks one as the panel's list does, and the choice stays. An unknown one, or a request that cannot be built (`HttpPanel::lastError`, e.g. `{{host}}` with no environment selected), answers with the environments available. The window side starts the run (`http_send`) and AgentTools polls `http_poll` (Stop sends `http_stop`), because a request can take up to the panel's timeout. Results come from `HttpPanel::requestFinished` and are turned into JSON at once (`noteHttpForChat`): status, reason, ms, headers (cookies, Authorization and API-key headers hidden), the body as text (JSON indented) clipped to 12 KB, binary bodies only described. Every string is then masked one by one (`maskedJson`). Masking the serialized JSON once ate an escape inside the body and broke the whole answer. A 4xx / 5xx shows as a failed row, and the model still gets the body. The call asks first, and the dialog shows the request as written (variables not filled in, so no environment secret appears). Tested with Gemini 3.5 Flash-Lite on the echo server of `httpdemo`. Without an environment the answer named `dev` / `down`. With `environment: dev`, Login went first and the token-authenticated request answered 200, the model quoting the echoed `Authorization` as `[hidden]`.

**Debugger tools** (group `jvm_debug`; `agent/AgentToolsDebug.cpp`, window side `window/MainWindowIdeDebug.cpp`): `debug_breakpoints` (add / remove / clear / list; through `m_breakpoints`, the editors' gutters and `breakpointsEdited`, so they are saved and shown like the user's), `debug_start` (opens the file and calls `startDebug`, so a main function, a Kotlin script or the Gradle / Maven project start as with Shift+F9; a running session is replaced without Debug's question), `debug_state` (reason, exception, top 15 frames resolved to project files, the frame's variables, or with `object_id` an object's fields), `debug_step` (over / into / out / continue), `debug_evaluate` and `debug_stop`. Variables and evaluation use `DebugSession`'s token answers (`variables`, `evaluated`), waited for 5 / 10 s on the window side. A start or step waits on the AgentTools side, polling `debug_state` with `brief` (no variables), until `MainWindow::m_debugStops` (counted on `DebugSession::stopped`) has moved or the session ended (`m_debugEndReason`). The wait is 120 s for a start (builds count) and 10 / 30 s for a step / continue, then answers with the full state. A program that never stops gets a note pointing at `terminal_output`, since the program runs in the terminal. Only the start asks first. Tested with Gemini 3.5 Flash-Lite on a lone `Orders.java` (an off-by-one loop): breakpoint, start, step into / over, `items.size()` evaluated, the cause explained, session stopped and breakpoints cleared, and in a second run the `items` list expanded. The test turned up a QODE bug, fixed separately: Java main detection ran `java Item` for a `record Item` declared above `main` ([jvm.md](jvm.md)). The group adds about 770 tokens.

**Undo / redo**: every file change the tools make is recorded in `agent/AgentJournal` (`Journal`, one per chat, persisted as `agent-chats/<id>.journal`; ops are Text (whole before/after), Move, Trash (delete → the trash path), Copy; consecutive edits of a file in one turn merge). `Journal::undo(Scope{turn|Last|All, path, startLine/endLine, force})` reverts in reverse order with a conflict check (a file the user changed after the agent is left alone unless `force`); with a line range it reverts only the `GitDiff` hunks touching those lines. Redo is a stack of undo groups. Everything reaches files through `FileAccess` (set by `AgentPanel`: open buffers are replaced through `CodeEditor::applyTextEdits` and saved with `saveQuietly`, so tabs and the git status stay in sync; `projectChanged` → `MainWindow` refreshes git + the file index). Independently of the journal, every file the agent saves, writes, creates or deletes also gets a local history version (`LocalHistory::Reason(QodeEdit)` in `AgentPanel`, see [editor.md](editor.md#local-history)), which outlives the chat. The model uses the `list_changes` / `undo_changes` / `redo_changes` tools; the UI has Undo/Redo buttons under each turn, the history menu, and `/undo [all]`, `/redo`.

**Slash commands** (`AgentPanel::runSlash`, popup while typing `/`): `/init` writes AGENTS.md through a normal agent run (refuses when it exists; `AgentRun::systemPrompt` appends AGENTS.md to the system instruction), `/compact` asks the chat's own provider (non-streaming `GeminiClient` / `ClaudeClient::generate`) for a summary stored as a `summary` message — `Session::history()` starts at the last summary.

**Caching**: Gemini caches a repeated request prefix implicitly, so the system prompt/tools are constant, each user message is stored with the exact text sent (`Message::sent`, editor context included) and replayed verbatim, and old tool results are only pruned when the context exceeds ~240k chars (then all at once). **Time and tokens** are shown per request, live: `AgentRun` times every request (`beginRequest` … `endRequest`; a retried request starts over) and emits `requestProgress(RequestStats)` four times a second, on every usage report, and once with `done` set (also for a stopped request). Neither API reports output tokens while streaming (Claude only in `message_start` and the closing `message_delta`, with `output_tokens_details.thinking_tokens`; Gemini in the chunks' `usageMetadata`, `thoughtsTokenCount` included), so the live count is the last reported one plus streamed characters / 4, shown with `~` until the server's figure replaces it. Claude's summarized thinking makes the live thinking estimate low until the exact count arrives. Thinking time runs from the first thought to the first answer text or tool call (from the request start when it opens with a thought), and "first token" is the time to the first streamed output. `AgentTurnView` shows a stats row at the bottom of the turn: live it is "Request N · …", afterwards the turn totals (wall time in `Message::ms`; "context" = the last request's input, shown before the summed "in total", since every request resends the whole conversation), and clicking it lists every request. The log is saved as `requestLog` in the chat; older chats show only the totals.

**Usage meter** (`agent/AgentPanelUsage.cpp`, `ai/AiPricing.h`): a text button in the header, "Run 18k · 33% cached  |  Chat 99k · $0.012". "Run" is the live turn (its finished requests plus `m_liveRequest`, the one streaming) or the chat's last turn; "Chat" sums every turn and the `/compact` summaries (their `promptTokens` / `outputTokens`). Tokens = input + output; the cache share is cached / input. The button is hidden until the chat has a request, and is refreshed by `rebuild()` and every `requestProgress`. Its menu holds one rich-text `QLabel` (`QWidgetAction`): requests, input, from cache, written to cache (Claude only), output, thinking and the estimated cost, for the run and the chat. Cost is worked out per request with the model of its turn: plain input × input rate + cache reads × read rate + cache writes × write rate + output (thinking included) × output rate. `RequestStats::cacheWrite` holds Claude's `cache_creation_input_tokens` (part of `prompt`), saved as `cacheWrite`. `AiPricing` holds standard paid-tier list prices: Claude from `claude-api-docs/models-pricing.md` (Haiku 5.5 costs more above 100k input per request), Gemini from Google's pricing page as checked on 2026-11-02. `gemini-3.5-flash` is retired and routed to 3.6 Flash, so it uses 3.6 Flash's rates; those rates double on 2027-01-01, which the table already applies by date. A model with no known price shows tokens only. Free tiers cost nothing, which QODE cannot know; the menu says the figure is an estimate. Update the table together with `AiModels`.

**Diagnostics after edits**: once a round of tool calls has run, every file its edits changed (`ToolResult::hasChange`, so `editor_command`'s formatting / import fixes too) that a language server checks is checked once, and the answer goes into the round's last edit of that file as `diagnostics_after_edit`: `{errors, warnings, list, more, fix, before, language_server}`. The list holds up to 30 errors in full; warnings are only counted. `AgentRun::runTools` / `runClaudeTools` therefore collect the round's results first and build the responses afterwards. The check is shown as its own row, "Check src/a.cpp for errors — 2 errors (1 new)" (block name `check_errors`, not a declared tool). The system prompt tells the model to fix the errors it caused before it answers, and to leave the ones marked as already there. Checking once per round, not after every edit, costs one wait per file, and a later edit in the same round may fix the error anyway. No check is made when a round ends the turn (`endsTurn`). `AgentTools::record` notes the file's errors before its first edit since the last check (`knownDiagnostics`: the server has not been told about the edit yet, because didChange is debounced), and after the check an error with the same source and message is marked "(was there before your edits)". When the server had never reported on the file (it was opened by the edit), `before` says some errors may be older. `filesToCheck` skips files without a server (`checksFile`: `LspManager::tracks` and the server running or starting; a missing or crashed one is never waited for).

`AgentPanel::collectDiagnostics` (also behind `get_diagnostics`) waits for the server (4 s for the tool; 30 s after an edit, when the server is known to be starting, e.g. the first Kotlin file of a session). It then calls `LspManager::syncNow` and waits until `diagnosticsVersion` reaches the version sent, up to 15 s (12 s for the tool), so the errors of the text before an edit are never passed off as current (see [lsp.md](lsp.md)). An answer that comes late carries a note saying it may be out of date. When a round edited several files, the first check also waits until reports have been quiet for 1.5 s (capped at 6 s), because a file's report can come before the server has taken in the other files' changes. Tested with Gemini 3.5 Flash-Lite against broken code. In C++ with clangd, the checks came back as "no errors" once Gemini had fixed `heigth` and a missing `;`. In Kotlin with kotlin-lsp, the check listed an argument type mismatch and an unresolved `count()`, and Gemini fixed both in the same run. A `compile_flags.txt` without `-xc++` makes clangd parse `.h` files as C (`'-std=c++17' not allowed with 'C'`, `std` undeclared); the model then sees those false errors too.

**MCP servers** (`mcp/`; the chat's side in `agent/AgentPanelMcp.cpp`). Stdio servers only (a program speaking newline-delimited JSON-RPC 2.0 on stdin / stdout; stderr is its log). `mcp::Client` runs one: `initialize` (protocol 2025-06-18, no client capabilities) → `notifications/initialized` → `tools/list` (paginated), Connected once the tools are known; `notifications/tools/list_changed` lists again, `ping` is answered and other server requests get -32601. **QProcess drops what is written before `start()`**, so messages are queued until `started` (without that the server never saw `initialize`). The start timeout is 180 s: uvx / npx download on the first start, and blender-mcp (mcp-for-blender 1.30) does a socket handshake with Blender's add-on before it answers (about 80 s when nothing answers on port 9876). Blender Lab's own "MCP" extension listens on the same port 9876 with a different framing (null-terminated JSON): when it owns the port, every mcp-for-blender call hangs until that server's 180 s socket timeout, so only one of the two add-ons may run. `fail()` sets the state and bumps `m_generation` before running the pending callbacks, otherwise the initialize callback reported the failure a second time. Each server runs in its own process group (`ProcessTree::track`); stopping detaches the QProcess from its client (its destructor would kill only the main process and block) and sends SIGTERM, then SIGKILL after 2.5 s. `callTool` waits in a nested event loop like `run_command` (5 min limit, polls `AgentTools::cancelled`, sends `notifications/cancelled` on Stop or timeout); a client deleted meanwhile fails its pending calls so the loop ends.

Configuration (`mcp/McpConfig`): Claude Code's shape `{"mcpServers": {name: {command, args, env, cwd}}}` plus QODE's `disabled` / `trusted`, in `~/.config/QODE-AGENTIC/mcp.json` (all projects) and `<project data dir>/mcp.json` (this project), both mode 0600 because `env` usually holds tokens (never shown to the model). Nothing goes into the project folder. A project server hides a global one of the same name, and `save` keeps the hidden global entry. `${VAR}` / `${VAR:-default}` are expanded in command, args, env and cwd. PATH gets ~/.local/bin, ~/.cargo/bin, ~/.bun/bin, ~/.deno/bin, ~/.npm-global/bin and /usr/local/bin, since a desktop launch often lacks them. `claudeCodeServers` reads `~/.claude.json` (user scope plus every project's local scope; the open project first) and the project's `.mcp.json`. Only `stdio` entries can be imported. `parseSnippet` accepts README snippets: `{"mcpServers": …}`, VS Code's `servers` / `mcp.servers`, a bare `"name": {…}` member, a single `{command…}`, and trailing commas.

`mcp::Manager` (owned by `AgentPanel`, re-created per project in `setProject`) starts the enabled servers when a project opens and restarts a client only when `sameLaunch` changes. Before each run `prepareMcpTools` hands the connected servers' tools to `AgentTools::setExtraTools`, so the declarations stay constant within a run. They are named `mcp__<server>__<tool>` (`[A-Za-z0-9_-]`, at most 64 characters, with a hash suffix when longer) and declared after the built-in tools: for Gemini as `parametersJsonSchema` (full JSON Schema; `parameters` is an OpenAPI subset), for Claude as `input_schema` (`$schema` / `$id` dropped, type forced to object). A call asks first through the same approval dialog unless the tool has `annotations.readOnlyHint` or the server is trusted; "Allow for this chat" covers that one tool. Results: text parts joined and clipped at 20k characters, `isError` → `{"error"}`, otherwise `{"output"}`. The chat row's summary is the first line, or for JSON (also JSON followed by prose, read up to `GarbageAtEnd`'s offset) its plain top-level values as `key: value · …`. The row's argument list leaves out `user_prompt`, which Blender's tools take on every call and which only repeats the user's message. Up to 4 images (png / jpeg / gif / webp, ≤ 5 MB base64) go in `ToolResult::images`: Gemini gets them in `functionResponse.parts[].inlineData` (multimodal function responses; `pruneOldResults` drops them from old turns), Claude as image blocks inside the `tool_result` content. `promptSection()` is appended to the system prompt: the connected servers with their `instructions` (clipped to 2k), and the configured servers that are not available, so the model can tell the user to check /mcp.

UI: View > Tool Panels > MCP Servers… (`MainWindow::showMcpServers` → `AiHub` → `AgentPanel::showMcpServers`), and the chat header's server button. Its menu lists each server with a status dot and has Show in the Chat (/mcp) and Manage MCP Servers…. `/mcp` adds a message with role `mcp`, rendered as a live `claudecode::McpCard` (shared with the Claude Code view: `setEmptyText`, `setManageLink`; Disable / Enable / Reconnect work on QODE's servers). `Session::history()` ignores the role. `mcp::McpDialog` has a list on the left and a form on the right: name, scope (This project / All projects), command (a whole command line typed there is split into program and arguments), arguments (`joinArgs` / `QProcess::splitCommand`), env as KEY=value lines, working folder, Enabled, Run its tools without asking. Below the form are the live status, the tool list, Log (stderr) and Test Connection, which starts the server as typed through a throwaway `Client` without saving. Import offers Paste JSON… and Claude Code's servers; with no servers yet, the empty page lists Claude Code's with one-click Add. Edits apply on Save / Apply, and Cancel asks about unsaved changes. Only the Gemini side has been run live with an MCP server: a test server (text and image results, the approval dialog) and Blender through mcp-for-blender (scene info, `look` screenshots, `execute_blender_code` edits).
