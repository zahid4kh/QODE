# Claude Code view

The chat area (`ai/AiHub`) has two pages in a `QStackedWidget`: the QODE chat (`agent/AgentPanel`) and **Claude Code** (`claudecode/ClaudeCodePanel`), a graphical front end for the `claude` CLI. The top bar has a button for each (`m_aiAct` sparkles, `m_claudeCodeAct` with `claudecode.svg`, Ctrl+Alt+C). A button shows its page, or hides the chat area when its page is already showing (`MainWindow::toggleAiPanel` / `toggleClaudeCode`). The page is remembered (`SettingsManager::chatPage`). `ClaudeCodePanel` is created when first shown (`AiHub::claudeCode()`; `AiHub` keeps the editors, project root, git-dirty flag and file list for it), or at startup when it was the page shown last. The Claude *models* of the QODE chat use `claude.svg`; `claudecode.svg` stands for Claude Code only. The top bar button, the view's logo and its send button use `Theme::claudeCode()` (#D97757) in every theme, unlike the themeable `brandClaude`.

Unlike the QODE chat, Claude Code does its own work: QODE runs the CLI in the project folder and renders what it prints. Files change on disk, not through the editor tabs, so `projectChanged` (debounced, after Edit/Write/MultiEdit/NotebookEdit/Bash results) refreshes git and the file index, and `EditorManager`'s file watcher reloads open tabs. There is no journal undo for its edits.

File links in replies are plain paths (`[x.cpp:42](src/x.cpp#L42)`, absolute paths, `file:` URLs, `path:42`), not `qode-open:`. `AiEdits::resolveFileLink` turns them into a file and line for `openFileRequested(path, line)`, which opens the editor column at that line. The QODE chat uses the same resolver.

Tool rows fold out (click anywhere on the row) into an IN / OUT card, like the VS Code extension. `AgentTurnView::addTool` takes the call in full as `input` (`inputText`: a Bash command as is, other tools one `key: value` per input field), and `ToolResult::output` carries the full result text. Only rows with an input get the chevron, so the QODE chat's rows are unchanged. The card is built on first open. IN shows up to 8 lines and OUT up to 16 before they scroll, and the wheel passes on to the chat at their ends. A Bash call with a `description` reads "**Bash** what it does" and keeps the command for IN. Edits keep their diff card instead.

## Around the input

- **Task list** (`ClaudeCodeTasks`): every `TodoWrite` of the main thread replaces the list pinned above the input (ring / half ring / tick per step; the header folds it to "3/7 done · what it does now"; more than 7 steps show a window around the one in progress). It goes away when the turn ends; the tool row stays in the turn. The CLI offers `TodoWrite` to current models only when `CLAUDE_CODE_ENABLE_TODO_TOOLS` is set (its default is on only for 4.x models), so `environment()` sets it to 1 unless the user's environment has a value. In `-p` mode the setting gives `TodoWrite`, not the interactive `TaskCreate`/`TaskUpdate` tools (checked with 2.1.304).
- **Files changed** (`ClaudeCodeChanges`): successful Edit / MultiEdit / Write results are summed per file (`noteChange`: counts and the first changed line of each `structuredPatch` hunk, past its leading context; an Edit without hunks finds `new_string` in the file). After the turn, `ChangesCard` lists the files ("N files changed · +a −r"); a row opens the file at its first change, "Review all" steps through every change in the editor. Files made or changed by Bash are not known and not listed. Saved conversations get the same cards.
- **Editor selection** (`ClaudeCodePrompt`): `setEditors` follows `EditorManager::cursorInfoChanged` / `currentChanged`. Selected lines of a file (never a secret file, see `AiEnv::isSensitive`) show as a chip in the input box and go with the next message as a text block in the wording of Claude Code's IDE extensions: `<ide_selection>The user selected the lines A to B from /abs/path:\n…</ide_selection>`. A selection is sent once; × leaves it out; selecting other lines brings the chip back.
- **Images**: `AiInput::setAcceptsImages` reports pasted images (a clipboard image is taken when its text is empty or only a link, or its HTML is an `<img>`: a browser's "Copy image" adds the address as text, while cells copied from a spreadsheet, which also bring a picture, stay text) and dropped image files. They are scaled to at most 1568 px, sent as PNG (JPEG when over 3.5 MB) `image` blocks, at most 8 per message. Chips and the bubble's thumbnails sit in a `FlowLayout` that wraps into rows: in a `QHBoxLayout` their summed minimum width widened the whole panel off screen.
- With attachments the user message's `content` is an array: images, the typed text, the selection block. Commands (`/…`) always go as plain text, since the CLI only runs them from a string; the attachments wait. The CLI saves the array as it was sent; `history::load` keeps the typed text as the prompt (blocks starting with `<` are context) and returns `images` and `selections` for the bubble.
- **Quotes** (Ask about this / Quote this in a reply's context menu, see agent.md): the pending quote is an `AiQuote` card above the chips, cleared with the transcript. It goes as its own text block `AiQuote::block` ahead of the typed text (it starts with `<`, so `history::load` does not take it for the prompt and returns it as `quote` for the bubble). Ask about this dispatches at once, or queues while a turn runs; a quote alone is not a message.
- **Active file** (`AttachmentBar::setCurrentFile`): the file of the active editor tab (never a secret file, a file outside the project or an untitled buffer) shows as a dimmed chip (the chip at 50 % opacity, a `QGraphicsOpacityEffect`). It is not sent. Clicking it attaches it (normal chip, × turns it back to dimmed). Switching tabs replaces a dimmed chip; an attached one stays until it is sent, and afterwards the chip is the dimmed one of the then-current file. A dimmed chip gives way to a selection chip of the same file. An attached file goes as its own text block `@relative/path` (`history::fileBlock`, quoted when it has a space): the CLI expands a mention in a stream-json text block as in typed text, so no file content passes through QODE (checked with 2.1.304: a "@a.txt" block was answered without a tool call). `history::load` returns such blocks as `files`, so the bubble shows "+ file …" again.
- **Prompt recall**: ↑ in an empty input (or on the first line of a recalled prompt left unchanged) shows the previous prompt, ↓ the next, ↓ past the newest empties the input (`AiInput::historyRequested` / `setRecalled` / `recalling`). The recalled text is ordinary text; typing leaves recall mode and the arrows move the caret again. While the `/` or `@` popup is open the arrows step it, and a recalled `/command` does not open the popup. The list (`m_recall`) is the terminal's prompts for this folder (`history::typedPrompts`: `~/.claude/history.jsonl`, one `{display, pastedContents, timestamp, project, sessionId}` per line, only its last 2 MB read, entries with pasted text left out because `display` holds a `[Pasted text #1]` placeholder), then the opened conversation's prompts, then what is sent here (commands too). Images and selections are not recalled. `-p` mode does not write `history.jsonl`, so prompts sent from QODE are recalled only in QODE.
- **Queue**: Enter while a turn runs queues the message (the send button is Stop only while the input is empty). After a turn that ended well the next queued message is sent. After Stop, an error or a crash the queue waits, with a note; "Send now" on a queued message interrupts the running turn (as Stop) and sends it next. The CLI is never written to mid-turn.

## /usage and /mcp cards

`/usage` and `/mcp` (exactly, no arguments) are not sent as prompts: `showInfo` puts the user bubble and a card (`ClaudeCodeInfo`) in the transcript and fills it from a control request, the same data the VS Code extension's Account & Usage dialog shows. They run at once, also while a turn runs (control requests are answered mid-turn), and the CLI is started if needed. Neither request calls the model. `Session::query` sends any control request and `answered(id, response, error)` brings the answer; `ClaudeCodePanel::query` keeps a callback per id, fails it after 60 s or when the process exits.

- **`get_usage`** (marked experimental in the CLI's schema, checked with 2.1.314): `subscription_type`, `rate_limits_available`, `rate_limits.limits[]` (`kind` session / weekly_all / weekly_opus …, `percent`, `severity` normal / warning / …, `resets_at`), `rate_limits.spend` (usage credits: `enabled`, `used` / `limit` as `{amount_minor, currency, exponent}`, `percent`), and `behaviors.day|week` (`request_count`, `session_count`, `recommendations[]` {title, detail, pct}, `skills` / `agents` / `plugins` / `mcp_servers` [{name, pct}]). The behaviours come from a scan of the last week's transcripts on this machine, so the answer can take a few seconds. Older answers without `limits` fall back to `five_hour` / `seven_day`. `UsageCard` shows Account (from `Auth::status()`, not the request), Usage (a bar per limit, coloured by `severity`, "Resets at …"), usage credits when enabled, "Manage usage on claude.ai" for claude.ai sign-ins, and "What's contributing" with a Day / Week switch. Without plan limits (API key) it shows the conversation's cost instead.
- **`mcp_status`**: `mcpServers[]` with `name`, `status` (connected / pending / needs-auth / failed / disabled), `error`, `transport` / `config.type` (`claudeai-proxy` = a claude.ai connector), `scope`, `tools[]`. `McpCard` lists them with a status dot, transport, scope and tool count; a click on a row lists the tools. Failed servers (and needs-auth ones that are not claude.ai connectors) get Reconnect (`mcp_reconnect {serverName}`), every server Enable / Disable (`mcp_toggle {serverName, enabled}`); after either the card asks `mcp_status` again. needs-auth gets a hint (claude.ai › Settings › Connectors, or `/mcp` in a terminal): `mcp_authenticate` needs an OAuth callback QODE does not offer. While a server is `pending` the card asks again every 2.5 s, at most 6 times. The QODE chat reuses the card for its own servers (`setEmptyText`, `setManageLink` → `manageRequested`, which opens its MCP dialog; see [agent.md](agent.md)), so the AgentPanel stylesheet repeats the `ccInfo*` / `ccFileRow` / `ccLink` rules.
- `InfoCard` builds its body into a fresh container widget every time (data, Day / Week, theme change) and deletes the old one whole: taking items out of the layout one by one deleted nested layouts twice and left their widgets behind.

## Status, context and notifications

- **Elapsed time**: the status line above the input reads "Working 1m 12s", "Waiting for you · 1m 12s" while a card is open (the clock keeps running) and "Stopping…". `agent::formatElapsed` ("12s", "1m 12s", "1h 03m") also gives the live "turn …" part of the stats row, so both read the same. `agent::useTabularDigits` asks for the font's `tnum` feature (Qt 6.7+) so the text does not shift every second.
- **Context meter** (`ContextMeter`, after the model and mode pickers): a ring painted in `paintEvent`, 16 px through `SettingsManager::scaled`. Track `Theme::border`, fill `accent` below 70 %, `warning` to 90 %, then `danger`. "Used" is the main thread's last request's `prompt + output` (`message_start` usage: input + cache read + cache creation; `message_delta` output), taken at every `message_stop`. Subagent requests carry `parent_tool_use_id` and never reach `onStreamEvent`, so they do not move it. The window is `result.modelUsage[<main model>].contextWindow` (the SDK's `ModelUsage`; with subagents there are several models, so the entry whose id matches `m_model`; 1M for Haiku 5.5 on 2.1.304). Until a result arrives it is 1M for ids ending in `[1m]`, else 200k; changing the model resets it. `system/compact_boundary` makes it unknown (empty ring, "Compacted: size known after the next reply"; `compact_metadata.pre_tokens` goes into the note). A new conversation empties it; opening a saved one reads the `usage` of the last main-thread `assistant` entry (`history::Conversation::contextTokens`; -1 when a `compact_boundary` follows it). A click sends `/compact` as a plain-text command, like the `/` popup (queued while a turn runs); no confirmation, the CLI reports it through `compact_boundary`. Disabled without a session id.
- **Desktop notifications** (`app/DesktopNotify`, `org.freedesktop.Notifications` over QtDBus, `QODE_HAS_DBUS`): when QODE is not the active window or the Claude Code page is hidden, a finished turn shows "Claude Code finished" with the reply's first line (or the error, or "Stopped"), and a permission / question / plan card shows "Claude Code is waiting for you" with "Bash: npm test" and the like. `QApplication::alert` is kept. A turn ended with Stop does not notify; queued messages that follow on notify once, after the last. Each panel uses keys `claudecode-<this>-finished|waiting` and `replaces_id`, so a second "waiting" replaces the first. The `default` action (a click) emits `showRequested` → `AiHub::claudeCodeRequested` → `MainWindow` raises the window and shows the page. Notifications close when the window gets focus (`QGuiApplication::focusWindowChanged`), and "waiting" when its cards are answered or withdrawn. The body is HTML-escaped (GNOME reads it as markup). Without QtDBus only the taskbar alert remains. No `QSystemTrayIcon` (GNOME has no tray) and no `notify-send` (may be missing). Setting `claudeCode/notify` (default on), toggled in the key menu.
- **Copy**: code boxes, the reply (the turn's footer) and user bubbles have Copy buttons; see `media/CopyButton` in [agent.md](agent.md).
- **Empty state**: under the (short) hint, when signed in with a project open, up to four suggestion rows (`suggestionList`): Explain this project; Review uncommitted changes (`setGitDirty`, fed by `MainWindow::onGitStatusChanged` through `AiHub`, since the panel never calls `GitRepository`); Run lint and fix, or Run the tests when no lint command is known; Set up CLAUDE.md (`/init`, sent at once) when the root has none. Commands come from file checks only (`package.json` scripts `lint` / `test` with pnpm / yarn / bun / npm by lockfile, `[tool.ruff]` in `pyproject.toml` or a `ruff.toml`, `Cargo.toml`, `go.mod`, `gradlew`). A row puts its prompt in the input to be edited, and Enter sends it. The rows are rebuilt (`refreshEmptyHint`) when the sign-in, the git status or the theme changes while the transcript is still empty.

## Files

- `ClaudeCodeCli`: finding the executable, the process environment, and `Auth` (sign-in status and the login flow).
- `ClaudeCodeSession`: one `claude -p` process with stream-json in and out, kept alive across turns.
- `ClaudeCodeHistory`: lists and reads the conversations Claude Code saved for the project, and the terminal's prompt history.
- `ContextMeter`: the context ring under the input.
- `ClaudeCodeInfo`: the /usage and /mcp cards.
- `ClaudeCodePrompt`: what one message holds (text, images, editor selection, attached file), the chips in the input box and the queue.
- `ClaudeCodeTasks`, `ClaudeCodeChanges`: the task list above the input and the files-changed card under a turn.
- `ClaudeCodePanel`: the view. It reuses `agent::AgentTurnView` (thinking, text, tool rows, `AiChangeCard` diffs, request stats), `AiInput` and `AiMentionPopup`.

## Finding `claude`

`executable()` searches PATH **with `~/.local/bin` prepended** (the native installer's location). `environment()` hands the CLI the same PATH. A desktop launch often lacks `~/.local/bin`, and this machine also has an old npm copy at `/usr/local/bin/claude`. Without the prepend, QODE would run a different `claude` than the terminal. Fallbacks: `~/.claude/local`, `~/.npm-global/bin`, `~/.bun/bin`, `/usr/local/bin`, `/usr/bin`. When nothing is found, the setup page shows the install command (`curl -fsSL https://claude.ai/install.sh | bash`) with Copy and Check again.

## Sign-in

QODE never reads Claude Code's credentials. It only runs the CLI:

- **Status** comes from `claude auth status --json`: `loggedIn`, `authMethod` (`claude.ai`, `console`, `api_key`), `email`, `orgName`, `subscriptionType`. The exit code is 1 when signed out, but the JSON is still printed.
- **Login** runs `claude auth login --claudeai|--console` without a terminal. The CLI opens the browser itself (xdg-open / `$BROWSER`), prints `If the browser didn't open, visit: <url>`, then `Paste code here if prompted >`, and reads the code on stdin. The redirect goes to platform.claude.com, which shows the code, so there is no localhost callback. `Auth` picks the URL out of the output once its line has ended. The view offers "Open the sign-in page" / "Copy link" plus a code field. `submitCode` writes the code plus a newline.
- **Wrong codes.** A code the CLI cannot parse (no `#state` part) prints `Invalid code. Please make sure the full code was copied.` and waits for another code *without a new prompt*. Its count is added to the prompt count, so the view re-enables the field with "That code was not accepted". A parsed but wrong code prints `Login failed: Request failed with status code 400` and exits 1. The view returns to the sign-in choices and shows that line. Cancel kills the process.
- **API key mode** (`claudeCode/auth = apiKey`, chosen on the sign-in page or from the key menu): `environment()` puts QODE's Claude key (`AiEnv::apiKey`) into `ANTHROPIC_API_KEY` for the CLI's processes only, never into a prompt. `auth status` then reports `api_key`. In account mode, `ANTHROPIC_API_KEY` is *removed* from the environment, because an inherited one would silently override the account the user signed in with.
- The status is checked on first show and again on every show while signed out (the user may have run `claude auth login` in a terminal). An error result or a process exit whose text looks like an auth failure (`/login`, `Invalid API key`, `authentication_error`, `401`, …) triggers a re-check, and a signed-out status brings back the sign-in page.

## The session protocol

`claude -p --output-format stream-json --input-format stream-json --verbose --include-partial-messages --permission-prompt-tool stdio --allow-dangerously-skip-permissions [--model M] [--permission-mode P] [--resume ID]`. This is the protocol of the Agent SDK. Without a type reference in this repo, the Agent SDK's `sdk.d.ts` / `sdk-tools.d.ts` (in any `@anthropic-ai/claude-agent-sdk` package) are the reference. Verified against CLI 2.1.304:

- **stdin**, one JSON object per line:
  - `{"type":"user","message":{"role":"user","content":"…"},"parent_tool_use_id":null,"session_id":"…"}`
  - control requests: `{"type":"control_request","request_id","request":{"subtype":"initialize"|"interrupt"|"set_model"|"set_permission_mode"|"get_usage"|"mcp_status"|"mcp_reconnect"|"mcp_toggle",…}}`
  - `initialize` is sent first. Its response lists the commands and skills with descriptions, which feed the `/` popup.
- **stdout**:
  - `system/init` (model, permissionMode, session_id, tools) arrives after the first user message, not at start. That is why the live turn heading gets the model through `AgentTurnView::setModel`.
  - `system/status` with `requesting` marks the start of each API request, which drives the request timer.
  - `stream_event` holds raw Messages API events. Text and thinking are shown from these.
  - `assistant` messages arrive one content block each, after that block's deltas. Their text and thinking are skipped when the message id was streamed. `tool_use` blocks become tool rows here.
  - `user` messages carry `tool_result`s, with structured `tool_use_result` (Edit/Write: `structuredPatch` hunks, which become the diff card, and `originalFile`).
  - `result` arrives once per turn. Its `total_cost_usd` is the **process's running total**, not the turn's: the panel adds it to what earlier processes of the conversation cost (`m_costBefore`). Cost is only shown when not on a subscription.
  - `rate_limit_event` drives the "N% of the weekly limit used" label.
  - Messages with `parent_tool_use_id` set belong to a subagent. Only their tool calls are shown, as "↳" rows.
- **Permissions**: `control_request` with `subtype: can_use_tool` (`tool_name`, `input`, `permission_suggestions`, `decision_reason`, `tool_use_id`). The answer is `{"type":"control_response","response":{"subtype":"success","request_id","response":{"behavior":"allow","updatedInput":…,"updatedPermissions":[suggestion]}}}` or `{"behavior":"deny","message":…}`. Each suggestion (`addRules` to localSettings for a command, `setMode acceptEdits`, `addDirectories`) becomes a button. `control_cancel_request` withdraws a prompt. Any other control request from the CLI (hooks, SDK MCP, dialogs) gets an error response, or the CLI would wait forever.
  - `AskUserQuestion` is answered by allowing it with `updatedInput.answers` = {question text → label(s), comma-joined for multi-select, or the typed answer}.
  - `ExitPlanMode` (the plan is in `input.plan`) is approved with `updatedPermissions: [{type: setMode, mode: acceptEdits|default, destination: session}]`, or denied with the user's feedback.
  - Answered cards are removed. The tool's row in the turn shows the outcome (the diff, the output, or the denial error).
- **Stop** sends `interrupt`. The CLI answers, emits a `user` "[Request interrupted by user]" and a `result` with `error_during_execution`. The process stays alive for the next message. If no result arrives within 6 s, the process is ended. A later message restarts it with `--resume`.
- **Process lifetime.** The process is started warm as soon as the chat page is ready, so the `/` list is filled and the first reply is faster. It is stopped on project change, a new conversation, an auth-mode change and sign-out (`closeWriteChannel`, then terminate, then kill). The conversation stays on disk, and the next message restarts the CLI with `--resume <session id>`. Model and mode changes go to a running process as control requests, and otherwise as flags at the next start. `--allow-dangerously-skip-permissions` only makes "Bypass permissions" reachable from the mode menu, which asks for confirmation. Sessions still start in the chosen mode.

## History

Conversations are `<CLAUDE_CONFIG_DIR or ~/.claude>/projects/<project path with every non-alphanumeric as '-'>/<session id>.jsonl`. The history menu lists them newest first. The title is the last `ai-title` entry, read from the last 512 KB, else the first real prompt. Files without either are skipped. Opening one renders the main thread: `user` / `assistant` entries without `isSidechain` / `isMeta` / `isCompactSummary`. Prompts are user entries whose content is not a `tool_result` and does not start with `<` (command output, reminders). Structured results are in `toolUseResult`. Only the last 40 prompts are rendered. `history::load` also returns the context size after the last reply, for the meter. The next message resumes the conversation with `--resume`.

## Testing without the UI

There is no test suite. The panel was exercised with a harness linked against `build/.obj/*.o`, minus `main.o` (`#define private public` before the project headers reaches the panel's internals; feed `onMessage` fake stream-json after setting `m_live` by hand instead of `dispatch`, which starts the CLI). It runs under `QT_QPA_PLATFORM=offscreen` (unset `DBUS_SESSION_BUS_ADDRESS` so no notification reaches the desktop; the offscreen pointer sits at 0,0, so a widget there counts as hovered), finds the input with `findChild<AiInput*>()`, invokes `sendRequested`, clicks "Allow" buttons and saves `grab()` screenshots. The sign-in flow was tested with `CLAUDE_CONFIG_DIR` pointing at an empty folder (signed out, the real login untouched), and with PATH and `BROWSER` pointing at a no-op `xdg-open` so no browser opened.

## Linux and Windows

- **Finding the CLI** (`ClaudeCodeCli::executable`): `~/.local/bin` (the native installer, `%USERPROFILE%\.local\bin` on Windows) goes first on the search path, then PATH, then `Platform::extraBinDirs` (Windows: npm's global folder with `claude.cmd`, pnpm, WinGet, Volta, Scoop; Linux: none). The PATH is split with `QDir::listSeparator()`.
- **Starting it:** always `Platform::setCommand` (npm's `claude.cmd` runs through cmd) and stop with `Platform::killTree` (otherwise the node behind `claude.cmd` keeps running). The session, `auth status` and `auth login` all do this.
- **Git Bash:** on Windows Claude Code runs its commands in Git Bash. When `CLAUDE_CODE_GIT_BASH_PATH` is not set, QODE sets it from `Platform::gitBashExecutable()`. The install hint says to install Git for Windows when it is missing.
- **Install command:** `curl -fsSL https://claude.ai/install.sh | bash` on Linux, the PowerShell installer (`irm https://claude.ai/install.ps1 | iex`, wrapped so it also runs from cmd or Git Bash) on Windows.
- History lives in `~/.claude` on both OSes (`%USERPROFILE%\.claude` on Windows), with the same layout.
- Checked on Linux on 2026-11-08 (CLI 2.1.314): install check and sign-in state shown. On Windows only the npm-installed CLI was tried (`--version`, `auth status`).
