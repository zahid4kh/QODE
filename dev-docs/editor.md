# Editor

## editor

`EditorManager` owns all open `Document`s (text + file state: modified flag, encoding, EOL, path) and their `CodeEditor` widgets (one per tab, plus a shared `FindBar`; tabs live in `EditorGroup`s — the leaves of a tree of QSplitters rooted at `m_root` — so files can sit side by side or stacked: `moveDocument` is the one primitive behind tab drag-and-drop onto a group's edge, the tab context menu, Split Editor Right/Down (Ctrl+\ / Ctrl+Alt+\), and `restoreLayout`; `m_active` is the group new files open in; `layoutState`/`restoreLayout` serialise the tree; a document is shown in exactly one group; emptied groups are removed with `deleteLater` since the drag originates inside their tab bar). Each tab hosts an `EditorPane` (file-local class in `EditorManager.cpp`: `Breadcrumbs` bar + `CodeEditor`); `WelcomePage` (empty state + recent projects) is the stack's first page. It drives save/close/prompt flows, and uses a `QFileSystemWatcher` (debounced via `m_changeTimer`) to detect external changes. Explorer file deletions/renames call back into `closeDocumentsUnder` / `pathRenamed`. Save flow: `saveDocument` → `prepareForSave` (format on save / trim trailing whitespace / final newline, one undo step) → `Document::save`; auto save (`autoSaveDocument`, timer or focus change) is silent, skips formatting while typing and never overwrites a file changed on disk. Syntax highlighting: `Language.cpp` defines per-language rule builders and registers file extensions in a `Registry`; `SyntaxHighlighter` applies them and tags every format with its `TokenRole` (`kTokenRoleProperty`) so bracket matching/folding can skip strings and comments. To add a language, write a builder in `Language.cpp` and register its extensions.

**Encodings and line endings** (`editor/TextEncoding`, Windows port Phase 4):
- Detection: a BOM decides (UTF-8 BOM, UTF-16 LE / BE), else strict UTF-8, else `Platform::legacyEncoding()` (Latin-1 on Unix as always, Windows-1252 on Windows). Both legacy encodings map every byte (Windows-1252's five undefined bytes keep their Latin-1 meaning), so a save writes the file back byte for byte; a typed character the legacy encoding cannot hold turns the file into UTF-8.
- A BOM followed by bytes that are not UTF-8 falls back to the legacy encoding (as before); a UTF-8 chosen by hand (Reopen with Encoding) shows bad bytes as U+FFFD.
- The status bar's encoding item is clickable: Reopen with Encoding (asks before dropping unsaved changes) and Save with Encoding. The LF / CRLF item switches the document's line endings (`Document::setLineEnding`, written on the next save). `.editorconfig` charset also takes utf-16le / utf-16be.
- Local history's diff and restore and the chat's file reads decode with `TextEncoding::decode` too; restoring into a closed file writes the stored version's own bytes.
- **Outside the editor** (2026-11-08): every read of a file the user owns goes through `FileManager::readText` (or `TextEncoding::decode` on bytes already read), never `QString::fromUtf8`, and every edit QODE writes back goes through `FileManager::writeText` / `textBytes`, which keep the encoding the file has on disk (UTF-8 for a new file) and use `writeFile` (atomic, Windows busy-file retries). Users: `.env` editor (also keeps CRLF on every line), HTTP env files, Ktor / Spring / version-catalog build edits, the Gradle wrapper upgrade, Expo's app.json form, the chat's undo / redo of closed files. QODE's own files (settings, caches, qrc templates) stay plain UTF-8. Do not open such files with `QIODevice::Text`: on Windows it rewrites `\r\n` byte pairs, inside UTF-16 too.

## editor extras (`CodeEditor`)

`CodeEditor` is spread over several files by concern: `CodeEditor.cpp` (setup, settings, painting, selections, hover, brackets, search), `CodeEditorFold.cpp` (what folds, hiding lines, fold markers), `CodeEditorTyping.cpp` (indentation, auto-pairs and tags, linked tag names, snippet stops, `handleKey`), `CodeEditorCompletion.cpp` (the popup, local words, `#include` paths, inserting items, Emmet), `CodeEditorGutter.cpp` (git hunks, blame, bookmarks, breakpoints, run markers, gutter clicks), `CodeEditorAssist.cpp`, `CodeEditorPredict.cpp`, `CodeEditorMulti.cpp` (multiple cursors), `CodeEditorLinks.cpp` (Ctrl+click links) and `CodeEditorLens.cpp` (code lenses). Helpers used by more than one of them (bracket tests, `protectedMask`, `relativeTime`, gutter widths) live in the private `CodeEditorText.h` (`namespace CodeEditorText`, pulled in with `using namespace`).

**Large files and long lines.** Measured in Xephyr: an 8 MB / 200 000-line JS file opens in about 1.1 s and types without stalls, but a minified file with one long line used to freeze. Three causes, all fixed:
- `SyntaxHighlighter::highlightText` searched every delimited rule's start again from `pos` after each string or comment, so a rule that never matched (a comment in JSON) rescanned the rest of the line each time: quadratic. Each rule's next match is now cached and only searched again once `pos` passes it.
- PCRE2 checks the whole subject for valid UTF-16 on every `match()` (only `globalMatch` iterations skip it), which again cost the line's length per match. `highlightText` checks the block once (`QStringView::isValidUtf16`) and then passes `DontCheckSubjectStringMatchOption`.
- Lines over `SyntaxHighlighter::kMaxHighlightedLine` (20 000 characters, VS Code's limit) stay plain and pass the incoming block state on.
Together these took a 480 KB one-line JSON from 6.8 s to 0.4 s to open. Separately, a single-block document is laid out eagerly by `QPlainTextDocumentLayout` on every document-wide change (font, tab stops), so `Document` gets the editor font and tab stops at construction and `CodeEditor::applySettings` only sets a font that differs (`setDefaultFont` has no equality check of its own). What remains on a multi-megabyte single line is Qt shaping that line (about 3 s per keystroke at 5 MB). `Document::isLarge()` (over 2 million characters or 50 000 lines when loaded) turns off the language server, the git blame and change gutter, the minimap, edit predictions and the folding of comments on open. `EditorManager::addDocument` calls `CodeEditor::setLargeFile` before attaching, and the breadcrumb bar shows a "Large file" note (`Breadcrumbs::setNote`, tooltip says what is off). Files over 20 MB still ask before opening.

always attach documents with `attachDocument()` (a `QTextDocument` keeps its own default font/tab stop, so plain `setDocument()` renders in the UI font). Emmet (`editor/Emmet`: parser + renderer producing snippet text, `findAbbreviation` finds the abbreviation before the caret; `CodeEditor::expandEmmet` runs on Tab after the snippet jump in HTML files and `.jsx`/`.tsx` (`setEmmetMode` from `EditorManager`), refusing inside `<style>`/`<script>`, attribute strings and — in JSX — anywhere an expression could not start) is inserted through `insertCompletion`. Indentation follows the file: `CodeEditor::indentUnit` detects tabs / the dominant step between nested lines (`detectIndent`) and only falls back to the settings. Snippets: `CodeEditor::insertCompletion` expands LSP snippets (`SnippetParser`; Tab / Shift+Tab walk the stops, repeated `$n` are mirrors copied by `syncSnippetMirrors`); `editor/Snippets` holds QODE's own per-language library (`LspCompletionItem::builtin`, prefix-match only, appended by `CompletionPopup::setItems(items, extra)`; unserved languages still pop up for them). Typing `>` auto-inserts the closing tag (`autoCloseTag`) and renaming a tag name edits its partner (`TagLink`, started in `beforeKeyEdit`, copied in `afterKeyEdit` inside one undo block). Enter in JS/TS/HTML/XML is tag-aware (`tagState` in `CodeEditorTyping.cpp`: indent after `<Tag` with unfinished attributes, after `<div>` or a lone `>`; `</` dedents). Auto-pairing (`CodeEditor::autoPair` / `eraseEmptyPair`: typing `(`, `[`, `{`, `"`, `'` or a backtick inserts the partner, typing the closer steps over it, a selection gets wrapped, Backspace between an empty pair removes both; not before a word, in strings/comments, or for apostrophes after a letter), bracket matching, indent guides (`paintEvent` overlay), code folding (regions from unmatched line-end brackets / block comments / indentation; fold flag in per-block `FoldData`; `applyFolds()` revalidates hidden blocks after edits) and the `MiniMap` overview widget all live in/around `CodeEditor`; breadcrumb symbols come from `Breadcrumbs::symbolChain` (indentation walk + per-language definition regexes). View-menu toggles persist in `SettingsManager`.

Folding on open: `CodeEditor::foldComments(header, docs)` (called by `MainWindow` one event-loop turn after a file is added, so the highlighter's comment state exists and the caret is placed) folds the block comment above the first code (a license header; a shebang may come first) and every `/** … */` of three lines or more; the region holding the caret stays open. Only for languages with C-style comments (`hasBlockComments`: Kotlin, Java, C/C++, JS/TS, Go, Rust …). View > Folding toggles both (`SettingsManager::foldLicenseHeaders` / `foldDocComments`, on by default).

Local completions (`setLocalCompletions`: build-file keys, Spring / Gradle properties, `@file:` annotations) may answer inside strings and right after `"` `:` `=` `@` / `/`: `completionTyped` asks for completion there when the provider has items, and the language's snippets are left out of such a list. Items that replace a whole argument (Maven coordinates) carry an edit range and a `filterText` that starts where the typed word occurs in them, since the popup anchors its match at the first character.

Run markers and tooltip provider: `setRunMarkers` puts ▶ icons in the light bulb's gutter column (click / Ctrl+Enter → `runRequested(line)`), `setTooltipProvider` answers text tooltips before diagnostics and hover; .http files use both (see [http.md](http.md)), and Kotlin / Java files get a ▶ on each `main` (Run / Debug menu, see [jvm.md](jvm.md)).

Breakpoints and the debugger's line (see [jvm.md](jvm.md#debugger)): `setBreakpointsEnabled` turns the line numbers into a click target (`breakpointAreaAt`: between the light bulb column and the fold markers); `m_breakpoints` follow edits in `trackLineEdit` like bookmarks and emit `breakpointsChanged`; a breakpoint is a `Theme::danger` disc behind its number (the number in `editorBg`) plus a faint danger line tint in `refreshSelections`; `setExecutionLine` adds a `Theme::warning` line tint and an arrow left of the number.

## C / C++ conveniences

`cpp/CppTools` (Qt Core only, works on text) holds the helpers; `window/MainWindowCpp.cpp` wires them. A headless test is cheap: compile `CppTools.cpp` with a small `main` against QtCore.

- **Switch Header/Source** (Alt+O, Edit menu, editor context menu): `CppTools::counterparts` (same folder first, then project files with the same base name, closest folder first); only when that finds nothing is clangd asked (`LspManager::switchSourceHeader`, its index knows pairs with different names).
- **`#include` completion**: in `CodeEditor`, `includeAt` (via `CppTools::includeContext`) makes the anchor the text after the last `/` (names may hold `.` / `-`), skips the word-only and string checks, and triggers on `/`, `<`, `"`. `<` after `#include` pairs to `<>` (`autoPair`; Backspace between them removes both). clangd's text edit already covers the closer the editor paired, but not when more was typed after the request, so `finishInclude` drops a doubled `>` / `"`; accepting a folder (`dir/`) puts the closer back (clangd's edit removed it) and asks again. Without a server the folders come from `setIncludeFolders` (MainWindow: the file's folder for `"`, include paths, the qmake project's `-I`, the project root, `CppTools::systemIncludeDirs` for `<`), files carrying their closer in `insertText`.
- **New files** (`ProjectExplorer::createFileIn` → `CppTools::newFileText`): a header gets `#pragma once`, or an include guard when most sampled project headers use guards (named after the first one: its prefix and suffix around its own base name, extension swapped); a source gets `#include` of its same-named header. `MainWindow` puts the caret below the starter text.
- **Generate Definition** (Alt+Enter on a declaration ending in `;`, also Edit menu / context menu): `CppTools::declarationAt` scans a copy of the text with comments, literals and preprocessor lines blanked (`blanked`, same offsets) from the top, block by block (`walk`: namespaces / classes / `extern "C"` descend, function bodies refuse; access labels reset the statement, `signals:` refuses), then `parseStatement` splits return type / name (operators, conversions, ctors) / parameters / qualifiers. Defaults, `virtual`/`static`/`explicit`/`override`/`final` go; `= 0/default/delete` and friends refuse; nested types in the return type get `Class::` (plus `typename` in templates); class templates add their `template <…>` line. Templates, `inline`/`constexpr` and anonymous namespaces keep the definition in the declaring file (after the outermost class). `insertionFor` jumps to an existing definition (same name and parameter types), else inserts after the definition of the nearest function declared before it, else before the one declared after it, else at the end of the matching namespace block or the file, qualifying with the namespaces not open there. A missing source file is created next to the header (`.c` in a C folder).
- **Smart `->`**: `LspClient` sends clangd's `editsNearCursor` completion capability, so after `.` on a pointer clangd lists the members with an edit that turns the `.` into `->` (without it, clangd offers nothing there). `CodeEditor::smartArrow` (in `showCompletions`, C/C++ only): when *every* item carries that edit (starting at the `.`, text starting with `->`), the receiver is a plain pointer, so the `.` becomes `->` at once (its own undo step) and the items are shifted to the text after it. A smart pointer gets both kinds of item (`get()` and the pointee's members), so its `.` stays; accepting a pointee member applies clangd's edit (`sp->sum()`). Snippets are hidden after `->` as after `.`.
- **Problems** (Tasks side tab, third view): compiler errors and warnings printed in the terminal; see `ProblemScanner` in [terminal-git.md](terminal-git.md). `TasksPanel::addProblems` / `clearProblems` keep them per terminal pane (`source`), and a 120 ms timer rebuilds the tree (grouped by file in first-seen order, `error` / `warning` pills, linker errors without a line). Clicking opens the location; the context menu has Fix with QODE (one problem; on a file row, that file's problems), Copy Message and Clear Problems, and the sparkles button in the header (shown while the view lists problems) starts a QODE chat about all listed errors (the warnings when there are no errors); see Fix with QODE in [agent.md](agent.md).

## inline edit box (Ctrl+K, "/?")

`ai/InlineEdit` is the box, `ai/InlineClient` its one streamed request without tools (Gemini `streamGenerateContent?alt=sse` with `thinkingLevel: low`, or Claude `/v1/messages` without thinking and with effort `low`; two retries on 429 / 5xx / network while nothing has streamed), `window/MainWindowInline.cpp` the wiring. It is not the chat and keeps no history beyond the open box. Ways in: typing `/?` (`CodeEditor::handleKey` drops the `?`, deletes the `/` and emits `inlineAskRequested(position)`; closing the box without asking puts `/?` back, so a literal `/?` costs one Esc), Ctrl+K (Edit > Inline Edit…) and "Ask about this to make a change" at the top of the context menu while text is selected (`setSelectionContextActions`; it shows Ctrl+K through the tab column, because two actions with one shortcut would be ambiguous). The target is whole lines: the selection's lines (a selection ending at a line start leaves that line out) or the caret line; an empty caret line is an insertion.

- **What is sent**: the whole file with the lines between `<<<MARKED LINES START>>>` / `<<<MARKED LINES END>>>` (or `<<<INSERT HERE>>>`), the marked lines again, the path, the language and the instruction. Files over 160k characters are cut to 700 lines on each side. `AiEnv::isSensitive` files are refused. The reply is the replacement text only; a code fence around it is stripped (`cleanReply`), leading blank lines too. A question gets `@@answer` + a short answer, shown as Markdown in the box (`flush` holds output back while it could still become `@@answer`). Follow-ups in the same box append to the box's own `contents` and ask for the complete text again.
- **Live proposal**: the reply goes into the document as `"\n" + text` right after the marked lines, updated every 40 ms (appended when the new text extends the old). The marked lines get `diffDelBg`, the proposal `diffAddBg` (`CodeEditor::setInlineMarks`, painted after the other extra selections; before a reply the target lines get a light accent tint). The first change opens an edit block and the later ones join it, so Accept (deletes the old lines in the same block) is one undo step back to the original. Reject removes the proposal in the same block and then undoes it, then clears the redo stack, so the undo history and the modified flag are as before. While a request or proposal is pending the editor is read-only and `Document::setSaveBlock` makes saves fail with a status message (auto save skips the document). `documentChanged` shifts the range for edits above it, ignores same-length changes whose text matches `m_snapshot` (highlighting reports format changes that way), and gives up, leaving the text, when something else edits the proposal.
- **Keys**: Enter sends (Shift+Enter: new line), Ctrl+Enter accepts, Esc stops a request / rejects a proposal / closes. Ctrl+Enter and Esc also work from the editor while the box is open. The header drags the box (it then stays put; a double-click puts it back under the lines); otherwise it follows the lines and flips above them when there is no room below.
- **Model**: `SettingsManager::inlineModel` (`ai/inlineModel`, default `gemini-3.5-flash`), chosen in the box's header from `ai/AiModels` (the lists the chat's picker uses too). A missing key shows "Set API key…" (`AiKeyDialog`).

## next edit predictions (Tab)

Cursor-Tab-like, but worked out from the text alone (no model, nothing leaves the computer). `editor/EditPredict` (Qt Core only) takes the whole text plus the user's edit (`Change`: [start, start + after) was `before`) and returns `Edit`s: **Rename** — the edit, trimmed to what really changed and widened to whole identifiers (plus one qualifier when it follows `.`/`->`/`::`, so `self.count` stays apart from `count`), turned one name into another (same number of segments, so typing `obj` → `obj.m` or a fresh word predicts nothing) → its other uses, skipping strings, member accesses of a plain name (`user.name` is not `name`, except when a function is renamed at its declaration) and the edit itself. When the name is a parameter of the enclosing function or declared locally in it (`let`/`const`/`var`, typed C/Java locals, Python `x =` / `for x` / `as x`, `:=`, `catch (e)`), only that function's range changes. **Parameter list** — the edit sits inside the `(...)` of a function declaration (`declarationAt`: `def`/`function`/`fun`/`fn`/`func`, JS/TS class methods, arrows bound to a name, typed C/C++/Java declarations, Kotlin/Java primary constructors; `constructor`/`__init__` map to the class name) and the parameter count changed by one → each call gets the parameter's name inserted as a selected placeholder, or loses the matching argument. Skipped: parameters with defaults / optional / variadic, calls with keyword or spread arguments, calls whose argument count does not fit, other declarations of the name; Python methods (`self`/`cls`) only match `obj.name(` calls with the index shifted. Function ranges come from the matching `{}` or, for Python and expression bodies, indentation (`declScope`); `enclosingFunction` scans up to 4000 lines back. A headless test of these cases is cheap: compile `EditPredict.cpp` with a small `main` against QtCore.

`CodeEditorPredict.cpp` is the editor side. `predictionChange` (on `contentsChange`) keeps `m_shadow` (the text before the latest change; changes whose text is unchanged are highlighter format updates and ignored) and the session: an edit touching the session grows it, one elsewhere starts a new session and drops the old predictions. Only the user's edits count: the editor must have focus, and undo/redo (`m_predictUndo`, set for the key and the context menu), snippet filling, our own applied edits (`m_predictApplying`, which only shift the session) and typing over a just-inserted placeholder (`m_acceptedFrom/To`) start nothing. 250 ms after typing stops (or at once on Tab) `computePredictions` stores the edits as `QTextCursor` pairs plus the text they must still hold. Tab (after snippet stops, before Emmet; not with a multi-line selection) goes to the next one at/after the caret: when it is off screen the first Tab only scrolls there; otherwise it applies it as its own undo step. Ctrl+Shift+Enter applies all as one undo step (the block starts at the first edit so undo leaves the caret there), Escape drops them, clicking the pill = Tab. Marks: next rename/removal struck through on `diffDelBg`, the others dotted-underlined in `accent`, insertion points a `gitAdded` bar; the pill (`Tab` key cap, `old → new` / `add x to f()` / `remove x from f()`, n/m, the Ctrl+Shift+Enter hint) sits after the target's line, or at the top/bottom edge with ↑/↓ line N when the target is off screen. Off for Markdown, CSV/TSV, JSON, HTML/XML, CSS, read-only and > 2M character documents; View > Next Edit Predictions (Tab) (`editor/editPredictions`, IDE option `edit_predictions`). In-file only: other files are not touched.

## multiple cursors

`CodeEditorMulti.cpp`. `textCursor()` stays the main caret and is always the newest one; `m_extraCursors` holds the others in the order they were added (so Alt+Shift+J, `removeLastOccurrence`, simply makes the last extra the main caret again). They are plain `QTextCursor`s on the document, so they follow every edit by themselves. `keyPressEvent` hands keys to `multiCursorShortcut` first (Alt+J next occurrence: the first press selects the word, and whole-word matching applies only when the selection came from that, as in VS Code; Ctrl+Shift+L / Ctrl+Alt+Shift+J all occurrences; Ctrl+Alt+Up/Down and Alt+Shift+Up/Down add a caret on the next line, lined up through `QTextCursor::setVerticalMovementX`; Alt+Shift+I carets at the ends of the selected lines), then, while there are extra carets, to `multiCursorKey`, before anything else (completion, snippets, tag links, auto-pairs, predictions all stay out of it). That handles movement (arrows, word moves, smart Home, End, with Shift), typing (an opening bracket or quote wraps each selection), Backspace/Delete (Ctrl: by word), Enter (keeps each line's indentation), Tab/Shift+Tab, and copy / cut / paste: a copy remembers its pieces (`m_multiClip`), so pasting with the same number of carets gives each its own piece, as does clipboard text with exactly one line per caret. Every edit goes through `editAtCursors`: carets in document order inside one edit block (one undo step per key), with `m_predictApplying` set so no prediction session starts. `normalizeCursors` merges carets that meet or overlap (the main one survives). Undo/Redo, Select All, Page Up/Down and any other Ctrl/Alt shortcut drop back to one caret first; undo restores only the main caret. Copy, Cut, Paste, Undo and Escape are window shortcuts, so `CodeEditor::event` accepts their `ShortcutOverride` while there are extra carets.

Mouse: Alt+press starts `m_columnDrag`; a release without moving toggles a caret at the click (`toggleCursorAt`), a drag selects a box (`columnSelect`: one caret per visible line between the press and the mouse, at the press and mouse x in content coordinates so horizontal scrolling does not shift it; lines too short to reach the box are skipped, unless the box is one column wide). Alt+Shift+press boxes from the main caret. A plain left click clears the extra carets. They are painted in `paintExtraCursors` (steady, they do not blink) and their selections by `appendCursorSelections` in `refreshSelections`. `cursorsChanged` updates the status bar ("Ln 3, Col 31 (3 carets)"). The Edit › Multiple Cursors menu shows the keys after a tab in the action text (no real shortcut, so Alt+J still reaches the terminal); the command palette splits such text into title and hint.

## Ctrl+click links

`CodeEditorLinks.cpp`. `linkAt(position)` looks, in this order, at the language server's document links (`setDocumentLinks`, cursors that follow edits; MainWindow asks `LspManager::documentLinks` with the colour request when the text settles and after a server comes up; clangd's `#include` targets, the JSON / CSS / HTML servers' URLs), a URL (`http(s)`, `ftp`, `file`; trailing punctuation and unbalanced closers are cut off), and a path under the mouse that exists as a file (`setPathResolver`, set in `MainWindow::wireEditing`: absolute, `~/`, relative to the file's folder, then to the project root), with an optional `:line[:column]`. `updateLink` underlines a link while Ctrl is held, ahead of the Go to Definition identifier; Ctrl+click opens URLs with `QDesktopServices` and emits `fileLinkRequested` for files (file:// links may carry `#L12` / `#L12,3`). The last path resolution is cached (`m_resolved`) because Ctrl+mouse moves ask again and again.

## code lenses

`CodeEditorLens.cpp` + `window/MainWindowLens.cpp`; View > Code Lenses (Run, References) (`SettingsManager::codeLenses`, on by default). The labels go after the line's text, not above it: `QPlainTextDocumentLayout` ignores block margins, so a line cannot be given extra height without changing the document (which would land in the undo stack). They are painted in `hintFont()` and the muted colour, separated by `|`, the hovered one in the accent colour and underlined (hand cursor); a click emits `codeLensClicked`. `m_lensEnd` remembers where a line's labels end so the inline blame of the caret line starts after them. `setCodeLenses` anchors each lens with a `QTextCursor` at its range start, so labels follow edits; a lens that is not resolved yet takes the label shown at the same line / column before, so labels do not blink while typing; `codeLensLabel` turns `$(play)` / `$(run)` into ▶ and drops other `$(icon)` markers. Unresolved lenses are asked for only once they are painted (`codeLensResolveRequested`, emitted from a zero timer, never from inside the paint), and answers for an older list are refused by `m_lensGeneration`.

`MainWindow::requestCodeLenses` runs with the other file-wide requests (`requestServerData`: 450 ms after an edit, after a server starts or asks for a refresh). QODE adds its own lenses first (`localCodeLenses`, no server needed so they show at once): for `.kt` / `.java` files of a Gradle / Maven project, "▶ Run Tests | Debug" on each class with tests and "▶ Run | Debug" on each test (`JvmTools::findTests`, see [jvm.md](jvm.md)), and "▶ Run | Debug" on main functions (`findMains`). The server's list is merged in when it answers for the same revision; kotlin-lsp's `intellij.jvm.runMain` lenses on a line that already has QODE's are dropped. A failed or superseded request leaves the shown list alone (or shows QODE's own when there is none yet). Resolved lenses titled "0 implementations" are blanked (jdtls counts them on every class and method). `runCodeLens`: `qode.runTest` → `MainWindow::runTest`, `qode.runMain` and `intellij.jvm.runMain` → `runMain`, a command whose third argument is a location array (jdtls `java.show.references` / `java.show.implementations`, VS Code's `editor.action.showReferences`) → `showLocations` (the Find References list, split out of `showReferencesAt`; `ReferencesDialog::setReferences(…, implementations)` words it as implementations), a command the server lists in `executeCommandProvider` → `workspace/executeCommand`, anything else a status-bar note.

## .editorconfig

`editor/EditorConfig` (Qt Core only; a headless test is a small `main` against QtCore) reads every `.editorconfig` from the file's folder up to the first with `root = true`; nearer files and later sections win, `unset` clears a value, parsed files are cached by path + mtime. Globs follow the spec: no `/` means any folder, `*` stops at `/`, `**`, `**/` (also zero folders), `?`, `[a-z]` / `[!x]`, nested `{a,b}` and numeric `{1..3}` (capture groups checked after the match). `Document` reads the properties in `load()` (and in `saveAs()` under a new name, and `refreshEditorConfig()` when a `.editorconfig` is saved; EditorManager then re-applies them to every open file): `end_of_line` and `charset` (utf-8, utf-8-bom, latin1) decide how the file is written, so the status bar shows them at once; `tab_width` goes into the tab stops before the text is set. `EditorManager::addDocument` gives the editor `indent_style` / `indent_size` / `tab_width` (`CodeEditor::setIndentOverride`; `indentUnit` prefers it to the detected indentation, `tabWidth()` replaces the tab-size setting in the editor), `prepareForSave` takes `trim_trailing_whitespace` / `insert_final_newline` over the settings (`insert_final_newline = false` only stops QODE adding one; it does not strip), and the language server formatter gets the same tab size / spaces. `max_line_length` and utf-16 charsets are not used.

## local history

`history/LocalHistory` (Qt Core only) keeps copies of files in `~/.local/share/QODE-AGENTIC/history` (mode 0700), one folder per file (the SHA-1 of its path) with a `path` file and the versions as `<msecs>-<kind>-<content hash>.z` (`qCompress`). `record` skips content equal to the newest version, files over 2 MB and binary files, keeps 100 versions per file, and lets an auto-saved version replace the auto-saved one of the same minute (auto save would otherwise store one per typing pause); `prune` (30 s after startup) drops versions older than 30 days. Where copies come from: `Document::saveAs` calls `recordWrite` (the bytes on disk first, as "On disk", when no version has them yet — the original before the first save, or a change made outside QODE — then the bytes written), labelled by the thread's `LocalHistory::Reason` (`AutoSaved` in `EditorManager::autoSaveDocument`, `QodeEdit` around the agent's saves and journal writes in `AgentPanel`, `Refactor` in `MoveController`); files written without an editor (`AiWorkspace` creates, `MoveRefactor::writeText`, the agent journal's `writeText`) record themselves. `FileManager::removePath` and the agent's delete / undo removals call `recordDisk(..., BeforeDelete)` (a folder: its text files, at most 3000, skipping `.git`, `node_modules`, build output); renames and moves (`FileManager::renamePath`, `MoveController`, the agent's moves) call `pathMoved` so the versions follow the file.

`history/LocalHistoryDialog` (File › Local History…, the editor's context menu, the explorer's context menu on a file, folder or the project) lists the versions, newest first, and compares the selected one with the current text (open editor first) or with the version before, in `git/DiffPane` (the side-by-side view split out of `DiffDialog`, shared by both). For a folder it first lists every file with versions under it, deleted ones marked. Restore (`MainWindow::showLocalHistory`): what gets replaced is stored as "Before restore" (the unsaved text, else the disk bytes, so the following save finds nothing new on disk), then an open file gets the text as one undo step and is saved without format on save; a closed or deleted file is written and opened.

## palette / project files / search

`palette/PalettePopup` + `FuzzyMatcher` back the command palette (`MainWindow::showCommandPalette` flattens every menu action, re-emitting `aboutToShow` for lazy menus) and Quick Open / Go to Line (`showQuickOpen`). `project/ProjectFiles` is the background file index (`git ls-files`, else a pruned directory walk). `search/ProjectSearch` (worker thread; unsaved buffers override the disk copy; also holds the shared replace helpers) and `search/SearchPanel` (third side tab) implement Find in Files with replace. `format/Formatter` shells out to installed formatters (clang-format, prettier, black, gofmt, rustfmt, shfmt, stylua). When none exists for a file type, Format Document / Format on Save fall back to the language server (`EditorManager::setLspFormatter` → `LspManager::formatting`, a blocking `textDocument/formatting` with a 3 s timeout, edits applied via `CodeEditor::applyTextEdits`).

## editor navigation extras

Go to Symbol (Ctrl+R) uses `Breadcrumbs::documentSymbols`; sticky scroll (`CodeEditor::paintStickyScroll`) reuses `Breadcrumbs::symbolChain`; git blame is `GitRepository::blame` (`git blame --porcelain --contents -`, so unsaved edits show as uncommitted) fed by `MainWindow::refreshGutter` into `CodeEditor::setBlame` (gutter column + caret-line annotation, both View/Git toggles).

## tasks / bookmarks

`tasks/TasksPanel` is the fourth side tab: project TODO/FIXME/HACK/XXX/BUG comments (a `ProjectSearch` run with a comment-anchored regex, rescanned on save; a second alternative of the pattern matches Kotlin's `TODO("reason")` / `TODO()` calls, which `onResults` keeps only in .kt / .kts files and lists as TODO with the reason), bookmarks, and Problems (compiler output from the terminal, see the C/C++ list above). Bookmarks live in `MainWindow::m_bookmarks` (path -> 0-based lines, persisted as JSON by `SettingsManager::bookmarks`), are mirrored into each `CodeEditor` (`setBookmarks`; lines follow edits in `trackLineEdit`) and changed only through `MainWindow::applyBookmarks`.

## CSV / TSV

Shell scripts need no LSP for colouring: `shell()` in `Language.cpp` covers commands and builtins, keywords, `name() {` / `function name`, assignment names (coloured like the `$NAME` that reads them), `[ ]` / `[[ ]]` with the test operators, and `$…` expansions. Two highlighter features exist for it. A `DelimitedRule` with `interpolates` (double quotes) gets the language's `interpolation` pattern repainted inside it, so `$var` keeps its colour in `"…"` but not in `'…'`. `LanguageDefinition::heredocs` makes `SyntaxHighlighter::openHeredoc` treat the lines after `<<EOF` / `<<-EOF` / `<<'EOF'` as a string up to the terminator. The block state is `kHeredocState` + 4 × the terminator's index in `m_heredocWords`, + 1 for `<<-` and + 2 when quoted (no expansion), which stays clear of the delimited states 1..n. A comment must start a word (`${#arr[@]}` is not one). `Languages::forFile` falls back to the `#!` line when the name gives no language (`#!/usr/bin/env bash` → Shell, python → Python, node → JavaScript). `Document::applyLanguage` passes the first line and runs again when the first line is edited, emitting `languageChanged` so `EditorManager` updates the editor and the status bar. The explorer's file menu (`ProjectExplorer::addScriptActions`) shows Make Executable (`FileManager::makeExecutable`, adds x wherever r is set) for a script (`FileManager::isScript`: .sh/.bash/.zsh/.ksh or a `#!` first line), or a green, non-clickable "Executable" row once it has the permission.

`Language.cpp` registers `csv`/`tsv` as `LanguageDefinition::csv` languages: `SyntaxHighlighter::highlightCsv` colours column by column (block state = 1 + column of a quoted field left open across lines; the delimiter is detected from the first line unless fixed). `editor/CsvData` (Qt Core) parses delimited text into rows/cells that remember their raw offsets (`detectDelimiter`, `parse`, `encode`). The table view is `editor/CsvTable`: `CsvModel` reads the document's text and writes every edit straight back into the `QTextDocument` — one field at a time (quotes kept when the old field needed/had them, offsets of later cells shifted, so no reparse), structural ops (rows/columns/sort/paste) as one undo step — so undo, modified flag, saving and the text view stay in sync; `CsvTableWidget` = toolbar + `CsvTableView` (copy/paste as TSV, Delete clears, Enter moves down, header rename/sort/insert/delete menus). `EditorPane` (EditorManager.cpp) creates the table lazily; the Text/Table button lives in `Breadcrumbs::setTableToggle` and the caret / current cell is carried across the switch by character offset.

## media

`MediaPanel` is the right-hand side panel (third `Island` in `MainWindow::m_hsplit`, hidden until used) that previews images (`ImageView`: fit/zoom/pan, animated GIF/WebP) and videos (`QMediaPlayer`, only when Qt Multimedia is found — `QODE_HAS_MULTIMEDIA` in QODE.pro; created with the first video by `ensurePlayer`, since loading its FFmpeg backend takes ~90 ms) and lists file details. The panel, like `MarkdownPreview`, is created on first use (`MainWindow::mediaPanel()` / `markdownPreview()`, see [app.md](app.md) "startup"). `EditorManager::openFile` never opens image/video files as tabs; it emits `mediaRequested`, which `MainWindow::showMedia` handles. SVG stays a text file. The same right-hand island also hosts `MarkdownPreview` and live SVG preview (`MediaPanel::previewSvg`): the Preview button in `Breadcrumbs` / Ctrl+Shift+V (`MainWindow::togglePreview`) previews the current Markdown or SVG document and follows it while it is edited. Markdown needs no LSP: the `markdown()` rules in `Language.cpp` highlight it (fences, tables, setext, reference links, HTML, escapes…), `CodeEditor::setLanguage` forces word wrap for it, and `MarkdownPreview::polish`/`fitImages` keep the preview free of horizontal scrolling (wrapping code blocks, images scaled to the view). Code boxes show a Copy button (`media/CopyButton`) at their header's right while the pointer is over them (`MarkdownView::updateCopyButton`). Inline code is a pill painted by `MarkdownView::paintEvent`: translucent `editorFg` with a faint outline, because the chat draws the view transparent over `agentBg`, where an opaque shade of `editorBg` vanished in the light themes. Ctrl+wheel zooms a view in 10% steps (50–250%, not saved): `MarkdownView::zoomTo` scales the document font and every px length of the default stylesheet (`zoomedCss`, so headings and spacing follow) and renders again; while the zoom is the user's own, a badge with the percentage sits at the top right of the part of the view on screen (it follows the scroll areas around it) and resets to 100% when clicked. `AgentTurnView` keeps all views of a turn at the same zoom (`setZoom`, which shows no badge).

## Copy as Image

`media/CodeImage` draws code into a PNG for sharing, without capturing the screen. The picture has:
- the code on a rounded card in an editor theme's colours, with optional window buttons, title (the file name) and line numbers;
- a padded background: one of eight gradient presets, a colour, a custom gradient with an angle, a picture scaled to cover, or none;
- a soft shadow;
- the QODE mark (app icon + name).

Where it is triggered:
- **Editor.** Edit › Copy as Image… and the editor's context menu (`MainWindow::m_copyImageAct`) use the selection, or the whole file when nothing is selected. A selection over several lines takes whole lines; one inside a single line takes just the selected text.
- **Code boxes.** In the QODE chat, Claude Code and the Markdown preview, the context menu of a code box (`MarkdownView::codeBoxAt`) offers Copy Code as Image…. The language comes from the box's header cell.

`CodeImageDialog` is a non-modal window:
- A live preview, drawn at the screen's resolution and redrawn 40 ms after the last option change. The size label comes from `CodeImage::measure`, which lays the picture out without drawing it.
- The options. They are kept in `codeImage/style` (`SettingsManager::codeImage`, JSON).
- Copy puts the picture on the clipboard both as an image and as `image/png` bytes, since apps ask for one or the other.
- Save PNG… starts in `~/Pictures`, never in the project folder.

Implementation notes:
- **Colours.** The editor's highlighting (semantic colours included) is copied from its blocks' layout formats, keeping only colour, weight and italic: highlighter formats also carry letter spacing for inlay hints. Those formats are used only while the picture uses the theme they were made in. With another theme, or a code box, the lines are highlighted again by a throwaway `SyntaxHighlighter` in that theme. That loses the semantic colours, and loses comment or string state when a selection starts inside a comment or string.
- **Text.** Blank lines at either end and the indentation all lines share are removed. At most 400 lines are drawn (`kMaxLines`); the dialog says so when the rest was left out.
- **Scale.** Everything is laid out in device pixels (font `pixelSize` = size × scale), so glyphs are hinted at the output size and not scaled afterwards. A picture over 16 000 px on a side, or over 60 megapixels, is drawn at a lower scale.
- **Shadow.** The shadow is the card's shape in translucent black, blurred by three horizontal and vertical box passes over the alpha channel.
- **Colour choices.** The window buttons use the theme's `danger` / `warning` / `success`, so the Monochrome themes give grey buttons. The mark's colour is picked against the background's average colour (dark or light ink); on a transparent background it uses `textMuted`. The preset gradients are picture content, not interface colours, so they are the same in every theme.
- **Small padding.** At 0 padding no background is painted, so the corners outside the rounded card stay transparent. With padding under 32 px, the mark moves into a strip inside the card.
