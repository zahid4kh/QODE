# HTTP client (.http / .rest files)

Works in any project (or a lone file): `.http` / `.rest` files in the format of VS Code's REST Client and IntelliJ's HTTP client. Requests are sent from the editor (the gutter's ▶ run marker or Ctrl+Enter; Ctrl+Alt+R, VS Code's key, is QODE's workspace symbols) and answered in the **HTTP Client** panel of the right-hand island (View > Tool Panels > HTTP Client, File > New HTTP Request File…). The Spring Boot Requests tab shares the network and response code but keeps its own form-based client.

## module (`src/http`)

- `HttpFile` (Qt Core): `parse(text)` → `HttpFileParse` = requests (`HttpRequestSpec`: block line range, request line, `### title`, `# @name`, method, URL with `?`/`&` continuation lines, headers, raw body lines, `>> file` / `>>! file`, flags) + `@name = value` file variables. Blocks are split at lines starting `###`; a block without a request line (comments only) is skipped. Directives (`# @x` or `// @x`, before the request line): `name`, `no-redirect`, `no-cookie-jar`, `timeout N[ms|s|m]`, `prompt var description`. The body ends at the first tail line: `> {% … %}` / `> handler.js` (IntelliJ response handlers: **not run**, `handlerScript` makes the panel say so), `<> previous.json` (dropped), `>> out.json` (body saved next to the file; `>>` picks a free `-1`, `-2` name, `>>!` overwrites). `WEBSOCKET` / `GRPC` request lines parse but are refused when sent. Also holds the plain data types `HttpRequestData` (what goes out) and `HttpResult` (what came back, or the `QNetworkReply::NetworkError` as int).
- `HttpVars`: `HttpContext` (file dir, file vars, environment, `@prompt` answers, `.env`, named responses, Spring base) and `HttpResolver`. Precedence: prompt answers > file variables > environment (with VS Code's `$shared` merged under it); values are resolved recursively (depth 10). System variables: `$guid`/`$uuid`/`$randomUUID`, `$timestamp [offset unit]`, `$isoTimestamp`, `$randomInt min max` (max exclusive), `$datetime` / `$localDatetime` `rfc1123|iso8601|"Day.js format"` `[offset unit]` (units y M w d h m s ms), `$processEnv [%]NAME`, `$dotenv [%]NAME` (`%` = the name is itself a variable), `$shared NAME`, IntelliJ's `$random.uuid|integer(a,b)|float(a,b)|alphabetic(n)|alphanumeric(n)|hexadecimal(n)|email`, and QODE's `$springBase` (the Spring Boot app: `http://localhost:<running port | configured port | 8080>`; undefined outside a Spring project). Request variables: `{{name.response.body.<path>}}`, `{{name.response.headers.<Header>}}` and the same with `request`; the path is a small JSONPath (`$.a.b[0]`, `['key']`, `*` = whole body). `build(spec, ctx)` fills everything in and refuses to send (listing them) when any `{{…}}` stays unresolved: a literal `{{` in a body is rarer than a typo. Body building: `< ./file` lines insert the file's bytes, `<@ ./file` with variables filled in; `application/x-www-form-urlencoded` bodies join their lines (trimmed) without newlines; `multipart/*` bodies use CRLF; `X-Request-Type: GraphQL` (header removed) turns "query, blank line, variables JSON" into `{"query", "variables"}`. A `/path` URL takes the `Host` header, else `$springBase`; a URL without a scheme gets `http://`. Without a Content-Type a body starting with `{`/`[` is sent as JSON, else text/plain.
- `HttpEnv`: environments from IntelliJ's `http-client.env.json` + `http-client.private.env.json` (the nearest folder from the .http file up to the project root that has either; private values win) and VS Code's `rest-client.environmentVariables` in `<root>/.vscode/settings.json` (read as JSONC: comments and trailing commas stripped by `stripJsonc`). Nested objects/arrays are ignored. `.env` for `$dotenv`: next to the .http file, else the project root. QODE never writes these files; the chosen environment is `SettingsManager::httpEnvironment()` (per project).
- `HttpRunner` (Qt Network): one request at a time on its own `QNetworkAccessManager` with a session cookie jar (`clearCookies`, `cookieCount`; `@no-cookie-jar` sets the cookie load/save attributes to Manual). Redirects follow `NoLessSafeRedirectPolicy` unless `@no-redirect`. Default timeout 60 s (`setTransferTimeout`); a transfer timeout cancels the reply like `abort()` does, so `m_aborted` tells them apart (timeout → reported as `TimeoutError`). Bodies are read up to 64 MB. `describeError` words the network errors.
- `HttpUi`: shared pieces of both clients: the item roles, `HttpRowDelegate` (coloured method, text, status-coloured detail; HeaderRole rows are section titles), `HttpJsonHighlighter` (can be switched off for non-JSON text), `curl()`, the stylesheet of the flat text tabs, `methodColour` / `statusColour`.
- `HttpResponseView`: status line (code + reason coloured by class, ms, size, a note such as "Redirected to …" / "Body saved to …" / handler scripts skipped), Body / Headers / Request tabs, wrap, copy (an image is copied as an image), save body (`QFileDialog`), open in an editor tab (`openTextRequested` → `MainWindow::openTextInEditor`: an untitled tab, unmodified). JSON up to 2 MB is pretty-printed; larger text is cut at 2 MB; image/* (not SVG) is shown in a scroll area, falling back to a note when it does not decode; other binary types show their size. `addTool` lets the owner put a button on the tab row (the panel's history button).
- `HttpPanel`: header (Send all / Stop, clear cookies with the count in its tooltip, Variables toggle, close), file row (name, request count, environment picker with the source files in its tooltip; hidden when there are no environments), the request list (method, `### title` / `@name` / URL, last status of this session; click = go to the request, double-click = send, menu: Send, Go to, Copy as cURL, Copy URL) or the Variables list (file variables, environment, named responses, each resolved), and the response view. It follows a document through `setDocument(path, QTextDocument*)` (re-parsed 300 ms after edits; the tab closing clears it). Sending: `sendAt(line)` re-parses, finds the request whose block holds the line and queues the requests it reads responses of (`referencedNames` that have not answered this session, recursively, each once) before it; `sendAll` queues every request. `runNext` asks `@prompt`s (password echo for names with password / secret / token; answers kept for the session as defaults), builds, sends, stores named responses (`m_named[file][name]`), the last status per request (`m_last`, keyed by the request's label) and the session history (50, newest first, history button menu). In a chain, a failed or unbuildable request stops the rest (they would only fail on its missing response); Send all goes on. `runNext` is always called through a zero timer so a prompt dialog never opens inside a reply's signal.

## editor and window

- `editor/Language.cpp`: the `HTTP` language (`http`, `rest`): methods, URLs, header names, `@var =`, `{{…}}` (also inside JSON strings through `interpolation`), `###` lines as headings, `#`/`//` comments except directive lines (`# @name` gets the preprocessor colour), `< file` / `>> file`. `SyntaxHighlighter` now also interpolates inside single-line delimited rules (the no-end ones), which only HTTP's JSON strings use.
- `CodeEditor` gained two generic hooks: `setRunMarkers(lines, tooltip)` (play icons in the light bulb's gutter column, which also reserves the column when the bulb is off; the bulb wins on its own line; clicking one or Ctrl+Enter anywhere while there are markers emits `runRequested(line)`) and `setTooltipProvider(f)` (asked before diagnostics and the language server's hover; the HTTP panel answers for `{{variables}}`: value + where it comes from, or why it is undefined).
- `window/MainWindowHttp.cpp`: `setupHttp` (project root, `currentChanged` → `followHttp`, renames), `httpPanel()` (creates the panel in `m_rightStack` on first use: a request sent, the panel opened or a tooltip in a .http file; `followHttp` does nothing before), `wireHttp` per new editor (markers recomputed on every edit of an .http document; cheap: a parse of the text), `sendHttp` (sets the Spring base and document, shows the panel, sends), `newHttpFile` (save dialog in the project root, a commented starter file with `@baseUrl` = the Spring address or localhost:8080, opened beside the panel), `openTextInEditor`. `MainWindowIde` reports the panel as `http_client` in the IDE state.
- `explorer/FileIcons`: `arrow-left-right.svg` in the accent colour for `.http` / `.rest`.

The chat's `http_request` sends through the panel too: `HttpPanel::requestFinished`, `isBusy`, `lastError`, `environments` / `selectEnvironment` / `currentEnvironment` and `stopRun` exist for it; see [agent.md](agent.md).

## Spring Boot Requests tab

`spring/HttpClientView` keeps its form (endpoint / history / saved lists, method, URL, headers, body) but sends through `HttpRunner` (30 s timeout, cookies kept) and shows answers in `HttpResponseView`; connection refused while the app is stopped adds the "start it" link. Endpoints, history and saved requests have **Copy as .http Request** (`HttpFile::format`; relative URLs made absolute with the current base, `{id}` path variables → `{{id}}`). "Open in editor" goes out through `SpringPanel::openTextRequested`.

## Linux and Windows

No OS-specific code: requests go through `QNetworkAccessManager`. Read the text files around a request (`.env`, `http-client.env.json` and its private file) with `TextEncoding::decode`, never `fromUtf8`. Windows PowerShell 5's `>` writes UTF-16 LE with a BOM, and Notepad can add a UTF-8 BOM. CRLF goes away through `trimmed()`. `< file` bodies and saved responses stay raw bytes. The `.http` text itself comes from the open `Document`, which is already decoded.
