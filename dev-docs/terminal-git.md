# Terminal and git

## terminal

a from-scratch terminal stack: `ShellProcess` (forks a shell on a pty), `TerminalScreen` (VT escape-sequence emulator / cell buffer), `TerminalView` (rendering + input), and `Terminal` (one session with header/restart wrapping them), and `TerminalPanel` (the bottom panel: a tab strip, New Terminal = Ctrl+Shift+T; each tab is a `QSplitter` of `Terminal` panes that can be split right/down via the Split menu or the tab context menu, `exit` in one pane of a split closes it; tabs rename by double-click / context menu and the tab list with custom names is saved per project as `terminalTabs`, restored by `setSavedTabs` when the panel first starts; the Maximize button toggles the panel height; `MainWindow` only talks to the panel). Closing a tab (its × or the tab menu's Close) asks first when a pane in it runs a command (`Terminal::commandRunning`: the shell is not in the foreground, `Platform::shellInForeground`), naming it from the shell integration's command line (`runningCommand`); a tab at its prompt closes at once. Hiding the panel (Ctrl+J, ×) never stops anything, and quitting QODE or switching projects does not ask. `Terminal` tracks `m_booting`: a command sent while a fresh shell is still printing its startup output waits for it to go quiet (sending Ctrl+C into a booting shell used to kill it), and a stop/restart we cause prints no "Process exited" message. The terminal starts lazily (`ensureStarted`). File locations in the output (`path:line[:col]` with an extension, Python's `File "…", line N`) underline under the mouse and open on Ctrl+click (`TerminalView::linkAt` → `fileLinkActivated` → `Terminal` / `TerminalPanel::openFileRequested` → `MainWindow`); relative paths are tried against the nearest make "Entering directory" line above, then `setLinkFolders` (the shell's `/proc/<pid>/cwd`, then the panel's folder), and only existing files count. `ProblemScanner` (fed by `Terminal` with the raw shell output: UTF-8 decoded across chunks, escape sequences stripped, text before a mid-line `\r` dropped) picks out compiler diagnostics: gcc / clang / javac / mypy `path:line[:col]: (fatal error|error|warning): msg`, rustc `error[E…]: msg` + `--> path:line:col` on the next line, ld `file.cpp:(.text+0x…): undefined reference to …` (no line), `CMake Error at file:line (cmd):` (message from the next non-empty line), Kotlin through Gradle / Maven `e: file:///abs/X.kt:L:C msg` (`w:` = warning; also without `file://` and the older `: (L, C):` form) and Maven's javac `[ERROR] /abs/X.java:[L,C] msg`. Paths resolve like the links (make's "Entering directory", then the same folders) and must exist; duplicates are dropped and the list is capped at 2000. `Terminal::problemsFound` / `problemsCleared` → `TerminalPanel` (adds the pane as `source`; closing a pane or tab clears it) → `MainWindowCpp.cpp` → the Tasks panel's Problems view. A pane's problems are cleared when a new command starts: `runCommand`, a shell (re)start, Clear, or Enter typed while the shell itself is in the foreground (`shellInForeground`: `pgrp == tpgid` in `/proc/<pid>/stat`, so Enter inside a running program does not count). The only thing it types on its own is the optional startup command from `setStartupCommandProvider`: `MainWindow` supplies `PythonEnv::activationCommand`, which finds any folder in the project root holding `pyvenv.cfg` + `bin/activate` (any name) and sources the script matching the shell; a pending Run command is queued after it.

**Shell integration and failed commands** (`terminal/ShellIntegration`, applied by `ShellProcess::start` when no custom launch is set): bash, zsh and fish load small hooks that send OSC 133;C when a command's output starts, OSC 633;E;<command line> right after it, and OSC 133;D;<exit code> before the next prompt. The scripts are written to `~/.cache/QODE-AGENTIC/shell` (rewritten only when their text changed) and run after the user's own startup files. Bash starts as `bash --rcfile <cache>/bashrc -i`; `/etc/bash.bashrc` is still read before it, and the file sources `~/.bashrc` first, then puts its preexec in `PS0` (`$(…)`: runs for every command, not for an empty line) and its precmd first in `PROMPT_COMMAND`, so it sees the command's `$?` and returns it unchanged for the user's prompt. The command line comes from `history 1`; a command kept out of the history (leading space with ignorespace, a repeat with ignoredups) leaves `HISTCMD` where the prompt saw it and is sent as "". zsh gets `ZDOTDIR=<cache>/zsh` (the user's own `ZDOTDIR` in `QODE_USER_ZDOTDIR`): its `.zshenv` reads the user's `.zshenv` from their folder (or `$HOME`), its `.zshrc` sets `ZDOTDIR` back, reads the user's `.zshrc`, then adds `precmd_functions` (first) / `preexec_functions` entries, so shells started later read only the user's files. fish gets `--init-command "source <cache>/qode.fish"` (`fish_preexec` / `fish_postexec` events, which run after config.fish). Other shells (sh, dash) run without it. Checked with bash 5.2 (the user's own prompt and `.bashrc` intact), and with zsh 5.9 and fish 3.7 unpacked locally with a test home (their own startup files ran, the marks came, `ZDOTDIR` was the user's afterwards), zsh also as QODE's terminal shell. `TerminalScreen::handleOsc` emits `shellMark` for 133 / 633 while the cursor is where the shell put the mark; `cursorStableLine` counts lines from the first one ever printed (`m_dropped`: lines the scrollback has dropped or cleared), so the output's start survives scrolling. `Terminal::onShellMark` notes the start line on C and takes the output on D (only a D after its own C: prompts with their own integration, or the D after an empty line, do nothing). When the shell sent no command line, it falls back to what `runCommand` typed, else the screen text from where the prompt ended (the cursor at the first key typed after the last D) to the line above the output. A non-zero exit (not 130 / 137 / 143 / 146 / 148, i.e. Ctrl+C, kills, Ctrl+Z; not grep / rg / diff / test / which and similar commands whose code answers a question; not without any output) becomes a `FailedCommand`: the command, exit code, its output as the screen shows it (more than 160 lines: the first 40 and the last 120), the shell's folder and the compiler problems found meanwhile. Its "Fix with QODE" button (`primaryBtn`) floats at the bottom right of the pane until the next command starts (a C mark, `newCommand`); pressing it emits `fixRequested` → `TerminalPanel` → `MainWindow::fixFailedCommand` (see Fix with QODE in [agent.md](agent.md)).

**Windows** (Phase 3 of the port, see `plans/windows-port.md`):

- **ConPTY.** `ShellProcess`'s Unix pty code is untouched; on Windows it uses `platform/ConPty` (`ConPtyWin.cpp`).
  - The shell is still a QProcess. `ConPty::attach` replaces its create-process-arguments modifier: the STARTUPINFOEX carries `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`. It also clears `STARTF_USESTDHANDLES` and inheritance, and drops Qt's `CREATE_NO_WINDOW`; with that flag the process would not land on the console.
  - `CreatePseudoConsole` and its siblings are looked up with `GetProcAddress`: the SDK only declares them for NTDDI_WIN10_RS5, and Windows before 1809 then gets a message in the pane instead of a QODE that fails to start.
  - A `std::thread` blocks in `ReadFile` on the output pipe (anonymous pipes cannot be waited on). It appends to a mutex-guarded buffer and posts one queued `readyRead`.
  - `close()` closes the input pipe, then calls `ClosePseudoConsole` (programs still on the console get `CTRL_CLOSE_EVENT`), then joins the reader. So `drain()` in `onProcessFinished` has all the last output before `finished`.
  - `terminate()` = close; the 1.5 s kill timer stays. Tested: terminating a pane running `ping` takes about 40 ms and leaves nothing running. Ctrl+C (`\x03`) stops `ping` and the shell survives.
  - ConPTY sends `\e[?9001h` (win32-input-mode) and `\e[?1004h` (focus events) at start, and `\e[8;r;ct` on resize. The emulator ignores all three; plain VT input works.
- **Default shell.** pwsh, else Windows PowerShell, else `%ComSpec%`.
  - `Platform::terminalShells()` lists PowerShell 7, Windows PowerShell, Command Prompt, Git Bash (`bin\bash.exe` beside git) and WSL (only when `HKCU\…\Lxss` has a distribution). It is empty on Unix, so Linux shows no menu.
  - The + button gets a drop-down: "New <shell>", and Default Shell, saved as `terminal/shell` through `SettingsManager::terminalShell`. A split reuses its pane's shell; tab names drop `.exe`.
- **Shell integration.**
  - **PowerShell** gets its script with `-NoLogo -NoExit -EncodedCommand`, which runs after the profile: a `.ps1` would need an execution policy that allows scripts, and the default (Restricted) does not.
    - It wraps `prompt` (first statement `$global:?`; D carries the native exit code, or 1 for a failed cmdlet; then `633;P;Cwd=`).
    - It wraps PSReadLine's `PSConsoleHostReadLine` (C, then E with the accepted line).
    - `$__qodeOk`, when set, overrides `$?` (see ShellSyntax below).
  - **Git Bash** reuses the bash script. When `$OSTYPE` is msys or cygwin (this Git for Windows reports cygwin), it adds `633;P;Cwd=$(pwd -W || cygpath -m)`.
  - **cmd** gets `PROMPT=$E]633;P;Cwd=$P$E\…`: only the folder, no exit codes.
  - ConPTY on Windows 11 passes OSC 133 / 633 through unchanged.
  - `ensureFile` must close the old script before `QSaveFile` replaces it: Windows cannot rename over an open file, and the scripts were never rewritten.
- **Shell folder and "at the prompt".** These come from `Platform::processCwd` and `Platform::shellInForeground`.
  - On Unix they keep the `/proc` code they replaced.
  - On Windows the folder is the last `633;P;Cwd=` (`Terminal::m_shellCwd`). The shell counts as in the foreground when it has no child process newer than itself (Toolhelp snapshot).
  - `-1073741510` (STATUS_CONTROL_C_EXIT) counts as a stop, and where / findstr / fc as question commands.
- **QODE's own command lines** (`terminal/ShellSyntax`). `Terminal::runCommand` passes every line through `ShellSyntax::translate(line, shell)`, so callers keep writing sh.
  - **The sh subset it reads:**
    - words: single-quoted with `'\''`, or double-quoted without `$`;
    - a backslash escapes only quotes, space and shell characters, so `.\gradlew` stays one word;
    - `VAR=v` before a command;
    - `&&`, `||`, `;` and `|`;
    - one `( … )` around the whole line.
    - Anything else (`$VAR`, globs, redirections, `&`) goes through unchanged.
  - **Per dialect:**
    - Posix names: unchanged.
    - `bash.exe` / `sh.exe` (Git Bash): only `.\` becomes `./`.
    - `wsl.exe`: `.\` becomes `./`, and a drive path at the start of a word (`C:/x`, also quoted or after `=`) becomes `/mnt/c/x`.
    - PowerShell and cmd: `mkdir -p a b` becomes `$null = New-Item -ItemType Directory -Force -Path 'a','b'` or `(if not exist "a\" md "a") && …`. cmd also gets `\` in a program path with `/` (`./gradlew` is the command `.` to cmd).
    - PowerShell: `'…'` quoting, and an argument starting with `-` that holds a `.` is quoted too (PowerShell 5.1 splits `-Dx.y=z` at the dot). `a; if ($?) { b }` replaces `&&` (5.1 has no `&&`). A quoted program gets `& `. `cd` becomes `Set-Location -LiteralPath`.
    - Subshell and `VAR=` in PowerShell: `$__qodeOk = $false; Push-Location; $__qodeEnvN = $env:X; try { $env:X = '…'; … ; $__qodeOk = $? } finally { $env:X = $__qodeEnvN; Pop-Location }`. `VAR=` is hoisted to the whole line. A finally leaves `$?` true, hence `$__qodeOk`; this was verified in a ConPTY PowerShell, where a wrapped `cmd /c exit 4` reports 4.
    - cmd: `"…"` quoting, `&` for `;`, `cd /d`, and a child `cmd /d /s /c "set "X=v" && …"` for the subshell and `VAR=`, so nothing leaks into the pane.
  - **Outside the terminal:** `Platform::setShellCommand` (DevServer: npm, Spring, Ktor) runs the same translation for cmd, so `JAVA_TOOL_OPTIONS='…' .\gradlew bootRun --args='…'` works there too. `setCommand` writes its own cmd line (`setCmdLine`), untranslated.
  - **Stopping a server:** after Ctrl+C a `.bat` / `.cmd` (npm.cmd, gradlew.bat) asks "Terminate batch job (Y/N)?" and waits. `ProcessTree::stop(QProcess*)` writes "Y" and closes the input; on another language the end of input ends the batch anyway.
  - **Clear:** Ctrl+L, except for cmd at its prompt (Esc, then `cls`): cmd has no Ctrl+L.
  - **Which shell a line is for:** the startup provider and the venv prompt get `Terminal::shellFile()` (`bash.exe`, `pwsh.exe`), not the tab name (`shellName()`, without `.exe`). Without the `.exe` Git Bash looked like a Unix bash.
  - **Startup commands** are written per shell instead: `jdkStartupCommand` (`$env:JAVA_HOME` / `set "JAVA_HOME=…"`, `bin\java.exe` accepted) and `PythonEnv::activationCommand`. Git Bash puts the JDK on PATH as `$(cygpath -u '…/bin')` (MSYS splits PATH at `:`); WSL gets no JDK or venv line (a Windows JDK is no use in its Linux). For PowerShell the venv sets `VIRTUAL_ENV` and `PATH` itself (`Activate.ps1` meets the execution policy); for cmd it runs `activate.bat`. The pieces are joined with `ShellSyntax::sequence` (`" & "` for cmd).
- **Problems and links.** A path may start with a drive (`C:\`, `C:/`, `/C:/`) when a slash follows, so Unix output reads the same. MSVC / tsc / C# `path(line[,col]): error CODE: msg` is new: it reaches Problems (MSBuild's ` [x.vcxproj]` is dropped) and works as a link.

The chat's `terminal_output` tool reads panes through `TerminalPanel::panes` and `Terminal::recentOutput` / `commandRunning` / `currentDirectory`; see [agent.md](agent.md).

## git

no libgit2; everything shells out to the `git` CLI. `GitRepository` (owned by `MainWindow`) runs all git processes asynchronously (`run`/`runOp`), caches `git status --porcelain=v2 -z` (plus ignored paths and branches) and exposes `stateOf(path)` for files *and* folders (folders aggregate their strongest child kind). It refreshes on a debounce from: `.git` file watcher, explorer model changes, saves, app activation and a 10 s poll; refreshes are coalesced and stale replies are dropped via `m_generation`. Only commands that take user paths get `--literal-pathspecs` (it breaks `stash -u`). `GitPanel` is the Version Control tab (sections Staged/Changes/Merge Conflicts with hover actions, commit box + amend, history tab); `DiffDialog` is the modeless side-by-side viewer (its two panes are `DiffPane`, shared with the local history); `PatchDialog` shows `git show` output; `GitDiff` is the Myers line-diff shared by the gutter and the diff viewer. Status colours/badges in the explorer come from `explorer/GitItemDelegate`; the editor gutter markers (`CodeEditor::setDiffBase`, diffed live against `HEAD:<file>`) are fed by `MainWindow::refreshGutter`, which re-reads bases only when HEAD/root changes.
